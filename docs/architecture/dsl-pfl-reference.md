## 0. PFL 是什么（定位对照）

PFL 是"**声明即言说**"的模板式文本 DSL：
`@syntax` 定义句法模式（关键词+捕获变量排列）→ 内容声明（`名称 :: 类型 内容 ;`）按模式
解析为统一 AST → `@say` 言说模板 + `@revert` 褪回把 AST 渲染回自然语言。

| 维度 | PFL | Lv-00 DSL-A |
|---|---|---|
| 领域 | 哲学/自然语言文本 | 几何约束求解 |
| 核心循环 | 声明 → AST → **渲染回文本**（双向） | 声明 → AST → IR → **约束图/证明**（单向） |
| 语法注册 | 自举：`@syntax` 动态注册新句法类型 | 22 关键字硬编码 |
| 输出 | 自然语言模板 | 约束图 / SVG / 6 目标代码（ga_codegen） |

**定位差异**：PFL 的"渲染回文本"是语言一等能力；Lv-00 的"渲染"（SVG 导出、
ga_codegen）是手写 C 函数。这正是 PFL 最大的机制级启发点，但受"不推翻架构"约束，
只能作为未来扩展记录（见 R2）。

## 2. 高价值借鉴（R1-R9 详细）

### R1 可空变量 `$name??` + `$none` 空节点（→ S20/S21）

**PFL 设计**：`$name??` 缺失时在 **AST 层**产生空节点（`$none` 可精确匹配），
显式空输入绑定空字符串 `""`。选择指南：可选填 → `$name?`；必填但有默认值/需区分
"未传参 vs 传了空值" → `$name??`。`$if{name|有值|无值}` 替代表达式消费空态。

**对 Lv-00 的价值**：直接解决 S20/S21"构造可能不存在"的实现方案选择。
关键启发：**空态放在 AST 节点层（空节点标记），而非值层 null**——与 Lv-00 的
约束图节点模型兼容（图节点要么存在要么不存在，不存在即空节点），比引入 nullable
值类型贯穿表达式层更轻。`$if{}` 的三分支（有值/空值）对应几何"交点存在/平行无交点
→ 取回退值"。

**落点**（S20/S21 设计修正）：
- 新 AST 标记 `DSL_AST_OPTIONAL`（可选构造表达式），缺失时子节点为"空节点"标记。
- 新 IR：`IR_OPTIONAL_BIND`（绑定结果，可空）+ `IR_OPTIONAL_FALLBACK`（空则取回退），
  2 个新操作码（原预估 nullable 贯穿语义层，现收敛为 AST 层 2 指令）。
- `guard`（S21）desugar 到 `IR_OPTIONAL_FALLBACK` + 早退。

**可行性**：中。工作量 ~300-500 行（AST 标记 + 2 IR + 解释器 + 测试）。
原 S20 预估"语义层改造（大）"可下调。

### R2 `@say`/`@revert` 双向渲染 = 模板化生成/导出（架构启发，不执行）

**PFL 设计**：`@say 类别 : "模板"` 绑定渲染模板；模板变量系统：
`$name`（输出捕获值）、`$name:first`（重复变量首项）、`$name:each`（迭代每项 +
`$block{}` 迭代体 + `$@item`/`$@index` 迭代上下文）、`$if{}`（空态分支）、
`$literal`/`$eval`（是否二次求值）、`$@derive(规则, 实参...)`（纯函数调用）。
`@revert` 递归褪回，原子节点为终止。

**对 Lv-00 的价值**：Lv-00 的 `interop_export_svg`（SVG 导出）与 `ga_codegen`
（6 目标代码生成）本质就是"褪回"——把几何对象渲染成目标文本。PFL 把它抽象为
**语言级模板机制**：几何对象 → 命名渲染模板 → 输出。若 Lv-00 未来需要
"一个几何构造渲染成 SVG/Lean/Coq/C/Python 多种输出"，模板系统比手写 C 函数
可维护性高一个量级。

**约束**：ga_codegen 是已验证的 6 目标代码生成器，重写为模板系统属大重构，
违反"不推翻架构"。**只记录为架构启发，不立项**；若未来新增第 7 个渲染目标，
可评估模板化增量方案。模板变量系统（`:each`/`$@index`/`$if{}`）的具体语法
可在 S15/S20 设计中按需借用（见 R7）。

**可行性**：远期。工作量 >2000 行，不执行。

### R3 `@theory` 命名空间 + 只读导入 + 显式导出（→ S17 完整蓝图）

**PFL 设计**：
- `@theory 名 { ... }` 是**唯一**代码组织单元；文件路径即命名空间。
- 符号表分层：文件顶层作用域 + 每理论块子作用域；查找自内向外、跨文件。
- **导入符号只读挂载**；内部符号不泄露，除非显式 `@export`。
- `@from "路径" use 符号 [as 别名] | 理论块 [as 别名] | 理论块.符号 [as 别名] | *`
- `#!import-strict` 禁止通配符导入；循环依赖硬/软区分。
- 路径相对当前源文件解析，禁止超出项目根目录。

**对 Lv-00 的价值**：DSL-A 的 `load "euclidean"` 是全局加载（无作用域、无显式导出），
S17 命名空间设计可直接采用 PFL 蓝图：
- `namespace geo { ... }` 等价 `@theory`（子作用域 + 显式导出）。
- `import "euclidean" use parallel, midpoint`（只读挂载 + 别名）替代裸 `load`，
  解决全局名冲突。
- `import "euclidean" hiding collinear`（选择性隐藏）补充 PFL 的 `as 别名`。

**可行性**：中高（S17 原预估 2500-4000 行含此项；PFL 蓝图可减设计风险，
不改总量）。`@export` 显式导出语义与"load 全局可见"现状兼容性需评估
（决策点 D2）。

### R4 三级诊断码体系（→ DSL-A 错误处理升级，新增立项建议）

**PFL 设计**：55 个诊断码分三级——33 错误（Errors）+ 15 警告（Warnings）+
7 信息（Info）。每码有明确触发条件表；快速参考卡给"错误码 → 修复方向"索引；
`#!suppress`/`#!unsuppress`/`#!mode-lock` 控制警告抑制与模式锁定。

**对 Lv-00 的价值**：DSL-A 现错误处理是零散返回码（ParseFailed_* 已在 PFL 里
成套），无警告/信息分级、无修复方向索引、无抑制机制。这是**工程债务治理**范畴
的低成本高价值升级：
- 为 dsl_compiler 建立诊断码枚举（错误/警告/信息三级）+ 触发条件文档 +
  "错误码 → 修复方向"索引表。
- 警告示例：未引用命名对象、约束永不触发（M6 类）、`load` 符号冲突。
- 信息示例：自动命名生成（S7）、desugar 重写记录（S2/S9）。

**可行性**：低-中。工作量 ~400-600 行（诊断码表 + 触发点接线 + 文档）。
不改变现有 22 关键字与 IR，纯质量升级，符合"修 bug 不留工程债务"路线。

### R5 错误恢复（→ DSL-A 解析器多错误报告）

**PFL 设计**：解析错误不立即退出；以 `;`、`@` 关键字、`#!` 模式声明为**恢复点**，
跳过坏声明继续解析后续声明——一次编译报告多个错误。

**对 Lv-00 的价值**：DSL-A 的 `dsl_compiler_parse.c` 遇错即败（`dsl_parse` 返回
NULL）。引入恢复点（分号/块边界）后，编译一个长几何脚本可一次报告全部错误，
用户不用改一个错重编一次。

**可行性**：低。工作量 ~150-300 行（parse_stmt 错误分支 + 恢复点跳过）。
与 R4 配套（每个恢复的错误挂诊断码）。

### R6 严格元数 + 终端函数（→ 决策记录，印证 desugar 原则）

**PFL 设计**：推导匹配**严格基于元数**——模式项数与 AST 子节点数必须完全相等；
不支持"剩余参数展开"；推导函数是**终端函数**（输出纯字符串，不能再作为推导输入
做模式匹配）。性能上分支按首参数编译索引。PFL 文档自认列表展开是已知限制
（PFL-2025-664 未来扩展），但当前版本为可预测性**主动选择严格**。

**对 Lv-00 的价值**：**印证而非新增**——dsl-syntax-sugar-design.md 的
"desugar 到现有 IR、避免 IR 爆炸"原则与 PFL 的严格元数哲学同构：
语法糖展开后元数固定（`polygon(...points)` 在展开时确定顶点数），
不引入变参 IR，解释器与证明引擎保持可预测。建议把 R6 记为设计决策
（ADR 级）：**IR 层永远不引入变参/剩余参数操作码；变参只在语法层展开**。

**可行性**：0 行（决策记录，写进设计文档即可）。

### R7 重复变量 `$x+[分隔符]` + `:each`/`$@index`（→ S15 批量构造）

**PFL 设计**：`$items+[、]` 捕获"苹果、香蕉、橘子"（分隔符可配置，trim 首尾）；
`@say` 中 `$items:first` 取首项、`$items:each` 迭代每项（配 `$block{}` 迭代体 +
`$@item`/`$@index` 迭代上下文）、`$items` 直接引用时用实际分隔符拼接。

**对 Lv-00 的价值**：S15 批量构造（`sequence(i in 0..8) { ... }`）的**结果命名**
侧可借用：批量生成的几何对象族（等分点 P1..P8）由迭代上下文自动命名
（`$@index` 对应 i）。`$x+[分隔符]` 的"分隔符可配置列表捕获"对应
S8 列表字面量 `[A, B, C]` 的解析（变参捕获 + 分隔符）。

**可行性**：中（并入 S15，+100-200 行，不改 S15 总量）。

### R8 媒介变量 `$~x` + `@default`（→ S14 上下文，声明式替代 with 块）

**PFL 设计**：媒介变量 `$~precision` 尝试匹配标识符，失败不导致解析失败，
用默认值。`@default $~x = "..."` 声明默认；**作用域规则**：理论块内 @default
仅对该块生效、仅作用于当前文件不传播至导入方、内层覆盖外层。

**对 Lv-00 的价值**：S14 原设计是 `with unit=degrees { ... }` 块（显式进/出栈，
+1 新 IR 指令）。PFL 提供**更声明式**的替代：`default precision = 0.01;` +
`constraint { distance(A,B) = 5; }` 内隐式引用——无需块级进出钩子，
作用域规则（当前文件、内层覆盖外层）直接可用。**可替代 S14 的 with 块设计**，
省掉 +1 新 IR 指令（回到 0 新 op）。

**可行性**：低-中。工作量与 S14 相当但更简单（无块进出栈，纯符号表默认值链）。

### R9 推导编译索引（→ S19 case/match 优化）

**PFL 设计**：推导分支编译时**按首参数的结构名分组索引**；匹配先查索引，
只在与首参数相关的分支中精确匹配；多参数可编译为决策树（O(N) → O(log N)/O(1)）。

**对 Lv-00 的价值**：S19 case/match 谓词头分派（constraint/prove 内按谓词头
分派）可直接采用：约束谓词（parallel/perpendicular/collinear...）作为首参数
分组键，分派表索引替代线性扫描。Lv-00 现有 `axiom_rule_engine` 适用性启发
（图节点数 < 前提数提前拒绝）已类似，R9 是正式化。

**可行性**：低-中（并入 S19，+100 行）。

## 3. 中价值借鉴（R10-R12，简短）

### R10 Enigma 预处理层（远期设想，不建议执行）

**PFL 设计**：用户写类自然语言句子（"理解「X」为 Y"、"若 X 则 Y"、"主语 关系 宾语"），
预处理层**确定性翻译**为 @syntax+@say+内容声明；识别规则 + 词法约定 +
局限清单（嵌套句式/复杂条件/精确变量名需降级手动）。

**对 Lv-00**：对应"自然语言 → 几何构造"（"过 A 作平行于 l 的直线" →
`line m = parallel(l, A)`）。但几何描述歧义性远高于哲学句式（"平行于"的方向、
"过点"的线型），且 PFL 明确是"句式识别不是语义理解"。**仅记录为远期设想**，
不立项；若做，从固定句式表（作/过/交于/中点）开始，与 S16 模板宏联动。

### R11 `#!mode-lock` / `#!suppress`（严格模式参考）

**对 Lv-00**：`#!mode-lock` 锁定模式组合对应 Lv-00 的 `ENABLE_LAYER_VALIDATION`
编译期验证思想（验证开启后不可关闭）；`#!suppress` 警告抑制并入 R4 诊断体系。
低-中价值，并入 R4 实施。

### R12 `@depends`/`@depends-weak` 硬软依赖（S17 模块管理补充）

**对 Lv-00**：DSL 模块（load/import）间的依赖声明区分硬/软，循环硬报错软警告。
并入 S17 命名空间设计。中价值。

## 4. 不建议借鉴（表）

| PFL 机制 | 理由 |
|---|---|
| `$text[。]`/`$line`/`$until` 文本捕获 | Lv-00 是结构化几何 DSL，无自由文本捕获需求；S1 坐标字面量已覆盖数值捕获 |
| `#!cn-strict` 中文变量边界 | Lv-00 关键字英文，无中文贪婪匹配问题 |
| 哲学注释 `///` 提取 Markdown | Lv-00 用 C/Doxygen，DSL 层注释简单即可 |
| `$eval` 二次求值 + 沙箱 | Lv-00 无 eval 语义（声明式），沙箱无承载对象 |
| 褪回深度/访问栈（循环引用检测） | Lv-00 导出无递归引用 |
| 模式感知词法（模式栈） | Lv-00 22 关键字固定，无动态注册需求（除非 S16 模板宏落地后场景变化） |
| 自举语法（@syntax 动态注册） | 与"22 关键字硬编码 + S16 模板宏"路线冲突；模板宏是更贴合几何的扩展方式 |

## 7. 决策定稿（v1.1，全部采纳）
