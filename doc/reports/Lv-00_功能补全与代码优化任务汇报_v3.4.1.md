## 二、主要改进内容

### 2.1 线程安全改进（高优先级）

#### 修改文件: `src/func_block/func_block_preset.c`

**问题**: Windows 版本的锁初始化使用 `InterlockedCompareExchange` 但缺少完整的内存屏障，存在 TOCTOU 竞态条件。

**改进措施**:
1. 添加 `MemoryBarrier()` 宏定义，支持 Windows 和 POSIX 平台
2. 实现 `preset_library_lock_init_once()` 函数，使用"原子操作 + 双重检查锁定"模式
3. 添加自旋等待机制，确保其他线程等待初始化完成
4. 完善中文注释，说明线程安全机制

**关键代码**:
```c
/* 内存屏障辅助函数 */
#ifdef _WIN32
#include <intrin.h>
#define MemoryBarrier() _mm_mfence()
#else
#define MemoryBarrier() __sync_synchronize()
#endif

/* 改进的锁初始化函数 */
static void preset_library_lock_init_once(void) {
    if (InterlockedCompareExchange(&g_preset_mutex_initialized, 0, 0) == 0) {
        if (InterlockedCompareExchange(&g_preset_mutex_initialized, 1, 0) == 0) {
            InitializeCriticalSection(&g_preset_mutex);
            MemoryBarrier();  /* 确保初始化可见性 */
            InterlockedExchange(&g_preset_mutex_initialized, 2);
        } else {
            /* 自旋等待其他线程完成初始化 */
            while (InterlockedCompareExchange(&g_preset_mutex_initialized, 0, 0) != 2) {
                Sleep(0);
            }
        }
    }
}
```

### 2.2 内存管理修复（高优先级）

#### 修改文件: `src/func_block/func_block.c`

**问题**: `func_block_copy()` 中对选择器的深拷贝是浅拷贝，函数指针和 user_data 直接复制，可能导致悬空指针和内存泄漏。

**改进措施**:
1. 实现选择器的真正深拷贝
2. 深拷贝选择器名称字符串
3. 深拷贝候选解数值数组
4. 添加 user_data 生命周期管理（深拷贝回调和释放回调）

**关键代码**:
```c
/* 深拷贝选择器 - 改进版 */
if (src->selector) {
    dst->selector = lv00_malloc(sizeof(SolutionSelector));
    
    /* 复制基本字段 */
    dst->selector->solution_count = src->selector->solution_count;
    dst->selector->current_index = src->selector->current_index;
    dst->selector->compare = src->selector->compare;
    
    /* 深拷贝选择器名称 */
    if (src->selector->name) {
        dst->selector->name = lv00_strdup(src->selector->name);
    }
    
    /* 深拷贝 solution_values 数组 */
    if (src->selector->solution_count > 0 && src->selector->solution_values) {
        dst->selector->solution_values = lv00_malloc(
            (size_t)src->selector->solution_count * sizeof(double));
        memcpy(dst->selector->solution_values, src->selector->solution_values,
               (size_t)src->selector->solution_count * sizeof(double));
    }
    
    /* user_data 处理：使用深拷贝回调（如果提供）否则浅拷贝 */
    if (src->selector->copy_user_data && src->selector->user_data) {
        dst->selector->user_data = src->selector->copy_user_data(src->selector->user_data);
        dst->selector->free_user_data = src->selector->free_user_data;
        dst->selector->copy_user_data = src->selector->copy_user_data;
    }
}
```

#### 修改文件: `src/func_block/func_block_selector.c`

**问题**: `selector_destroy()` 仅释放选择器结构体本身，不释放内部动态分配的资源。

**改进措施**:
1. 释放选择器名称字符串
2. 释放候选解数值数组
3. 如果提供了释放回调，调用回调释放 user_data

**关键代码**:
```c
void selector_destroy(SolutionSelector *selector) {
    if (!selector) return;
    
    /* 释放选择器名称 */
    if (selector->name) {
        lv00_free((void **)&selector->name);
    }
    
    /* 释放候选解数值数组 */
    if (selector->solution_values) {
        lv00_free((void **)&selector->solution_values);
    }
    
    /* 释放 user_data（如果提供了释放回调） */
    if (selector->user_data && selector->free_user_data) {
        selector->free_user_data(selector->user_data);
    }
    
    lv00_free((void **) &selector);
}
```

#### 修改文件: `include/lv00/func_block.h`

**改进措施**: 扩展 `SolutionSelector` 结构体，添加深拷贝支持所需的字段：

```c

    ConstraintGraph *graph;
};
```

### 2.3 统一错误处理机制（高优先级）

#### 修改文件: `src/core/engine.c`

**问题**: 同时存在线程局部变量 `last_status`/`last_error` 和引擎实例级别的错误状态，容易混淆。

**改进措施**:
1. 设计并实现统一的错误处理系统 v3.4.1
2. 新增 `engine_set_error()` 函数 - 优先将错误存储在引擎实例中
3. 新增 `engine_clear_error()` 函数 - 清除错误状态
4. 新增 `engine_get_error()` 函数 - 获取完整错误信息
5. 保留线程局部变量作为早期错误回退机制

**关键代码**:
```c
/* 统一错误处理系统 v3.4.1 */

/* 线程局部回退状态 */
static LV00_THREAD_LOCAL EngineStatus g_thread_last_status = ENGINE_OK;
static LV00_THREAD_LOCAL char g_thread_last_error[LV00_ERROR_MSG_SIZE] = {0};

/* 设置引擎错误状态 */
static void engine_set_error(LV00Engine *engine, EngineStatus status, const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);
    
    if (engine) {
        engine->last_status = status;
        vsnprintf(engine->last_error, sizeof(engine->last_error), fmt, args);
    } else {
        g_thread_last_status = status;
        vsnprintf(g_thread_last_error, sizeof(g_thread_last_error), fmt, args);
    }
    
    va_end(args);
}

/* 清除引擎错误状态 */
static void engine_clear_error(LV00Engine *engine) {
    if (engine) {
        engine->last_status = ENGINE_OK;
        engine->last_error[0] = '\0';
    } else {
        g_thread_last_status = ENGINE_OK;
        g_thread_last_error[0] = '\0';
    }
}
```

### 2.4 悬空指针风险修复（高优先级）

#### 修改文件: `src/core/engine.c`

**问题**: 使用 `graph->next_node_id - 1` 推断函数块ID，如果图操作失败可能导致错误ID。

**改进措施**:
1. 使用 `graph_get_last_added_node_id()` 安全获取新节点 ID
2. 添加二次验证，确保 ID 对应的节点存在且类型正确
3. 使用新的错误处理接口设置错误信息

**关键代码**:
```c
/* v3.4.1 改进：使用 graph_get_last_added_node_id() 安全获取新节点 ID */
AddNodeResult result = graph_add_function_block(engine->main_graph, ...);
if (result != ADD_NODE_OK) {
    engine_set_error(engine, ENGINE_INVALID_STATE, "创建函数块失败（图操作返回错误: %d）", result);
    return false;
}

/* 安全获取新创建的函数块 ID */
int new_func_block_id = graph_get_last_added_node_id(engine->main_graph);

/* 验证获取的 ID 有效 */
if (new_func_block_id < 0) {
    engine_set_error(engine, ENGINE_ERROR_INTERNAL, "无法获取有效的函数块 ID");
    return false;
}

/* 二次验证：确保 ID 对应的节点存在且类型正确 */
GeomNode *new_fb_node = graph_get_node(engine->main_graph, new_func_block_id);
if (!new_fb_node || new_fb_node->type != GEOM_FUNCTION_BLOCK) {
    engine_set_error(engine, ENGINE_ERROR_INTERNAL, "函数块节点验证失败");
    return false;
}
```
