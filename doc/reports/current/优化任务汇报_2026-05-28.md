### ✅ 高优先级修复（已完成）

#### 1. apiClient.ts 内存泄漏修复 【安全修复 H-04】

**问题描述**:  
`combineAbortSignals()` 函数添加了事件监听器但未正确移除，导致内存泄漏。

**修复内容**:
```typescript
// 修复前
const onAbort = () => controller.abort();

// 修复后
const onAbort = () => {
  controller.abort();
  // 主动清理以防万一（虽然 once:true 应该自动处理）
  a.removeEventListener('abort', onAbort);
  b.removeEventListener('abort', onAbort);
};
```

**影响文件**: `web/gui/src/services/apiClient.ts`

**风险等级**: 🔴 高 - 内存泄漏会影响长时间运行的应用程序

---

#### 2. streamClient.ts 定时器泄漏修复 【安全修复 M-08】

**问题描述**:  
`scheduleReconnect()` 创建 `setTimeout` 但未保存定时器 ID，导致 `destroy()` 无法清理已调度的重连任务。

**修复内容**:
1. 添加 `reconnectTimer` 变量保存定时器 ID
2. 在 `cleanup()` 函数中清理重连定时器
3. 在 `destroy()` 时确保定时器被清理
4. 使用内部标志位 `autoReconnectEnabled` 替代修改 `opts` 对象

```typescript
// 新增：保存定时器 ID
let reconnectTimer: ReturnType<typeof setTimeout> | null = null;

// 在 cleanup() 中清理
if (reconnectTimer !== null) {
  clearTimeout(reconnectTimer);
  reconnectTimer = null;
}
```

**影响文件**: `web/gui/src/services/streamClient.ts`

**风险等级**: 🔴 高 - 定时器泄漏可能导致在组件销毁后仍访问已清理的资源

---

#### 3. formulaParser.ts 类型安全优化 【优化 H3】

**问题描述**:  
`executeFormula()` 函数中大量使用不安全的 `as` 类型断言，如：
```typescript
const { name, x, y } = cmd.args as { name: string; x: number; y: number };
```

**修复内容**:
1. 定义联合类型 `FormulaCommandArgs` 替代 `Record<string, unknown>`
2. 添加运行时参数验证函数
3. 为每个命令分支添加数值类型检查

```typescript
// 新增：类型安全的参数类型
export type FormulaCommandArgs =
  | { type: 'point'; name: string; x: number; y: number }
  | { type: 'segment'; p1Name: string; p2Name: string }
  // ... 其他命令类型

// 添加数值验证
if (typeof x !== 'number' || isNaN(x)) {
  cmd.error = `点 ${name} 的 x 坐标无效`;
  result.errors.push(cmd.error);
  break;
}
```

**影响文件**: `web/gui/src/utils/formulaParser.ts`

**风险等级**: 🟡 中 - 不安全的类型断言可能在运行时导致未定义行为

**问题描述**:

3. `setPoints/setSegments` 等方法未做防御性拷贝

**修复内容**:
1. 添加文档说明外部注册机制的设计意图
2. 修复快照恢复不对称问题，添加注释说明原因

```typescript

// 修复后
setPoints: (points) => set({ points: [...points] }),
```

**影响文件**: `web/gui/src/stores/geometryStore.ts`
