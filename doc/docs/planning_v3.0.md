Lv-00：几何元语言 · 最终完整设计 v2.9
一、根本精神
Lv-00 是一门以几何为唯一载体的双模数学元语言。几何体本身是计算的执行者、数据的承载者、证明的见证者。
几何即符号
点、线、区域本身就是程序的实体。一条线段同时是数据、变量、计算、证明。没有额外的标签或编码层，意义由形状和关系直接给出。
数形不二
数值只能是几何量——线段长度、圆弧弧度、区域面积、向量模长。改变一个数就是拉伸、旋转或变形一个几何体。系统拒绝任何“抽象数值”的文本形式单独存在。
构造即证明
一个构造是否构成对命题 P 的有效证明，取决于其外部端口与 P 的几何模式在合一算法下是否精确匹配——这是证明正确性的充要条件。图形能否无矛盾地闭合，是匹配成功的自然副现象。
在执行合一前，系统对构造图和命题模式图执行一次轻量级的图规范化遍（Graph Normalization Pass）：基于内核符号坐标判等，自动合并坐标完全相同的冗余节点。此规范化仅基于可判定的符号等价——不引入任何公理包的语义等价。当两个坐标相同的点属于不同作用域（不同的 parent_block_id 或 namespace_depth）时，系统提示用户确认是否合并，防止跨越构造语义层次。规范化步骤在证明导航器中作为“自动规范化”记录，用户可展开查看规范化前后的图差异。这一机制在不牺牲构造主义严格边界的条件下，大幅降低了用户手动处理“两个点坐标完全一样所以应该合并”这类机械操作的需求。
双重模态定位：Lv-00 在两个模态下运作。在可被直观几何化的数学片段（古典几何、集合论基础、基本范畴论、程序语义中的状态空间等）中，“拼图对齐”的几何事实提供了真正意义上的“看得见的正确性”——这是 Lv-00 相对文本形式化系统的认知优势。当数学对象的抽象层级超出二维几何直觉（如非交换代数结构、高维自然变换条件）时，Lv-00 提供的是统一的几何操作语法而非直接的几何直觉——端口连接成为主要交互载体，信任锚点从“视觉直觉”迁移至“端口连接操作的严格保真”。这并非设计缺陷，而是数学抽象本质的诚实反映。Lv-00 不对所有数学强行承诺几何直观——它只在几何直觉自然可及的范围内提供直观，在所有范围内提供统一语法。
“操作统一性能否在实践中降低高维数学建模的心智负担”这一假说，被明确标记为待验证的经验问题，将在 Lv-00 自举后的人因评估中作为核心度量指标接受检验。
全数学映射
Lv-00 的目标是成为全部数学的几何化身系统，提供统一的几何操作语法。系统诚实地承认二维画布对高维结构的表示存在物理上限：高维结构通过端口抽象来表达，二维矩形编码仅为投影视图之一。
公理中立
内核只提供关联几何引擎（点、线、区域的关联、之间、相交、包含关系）和图重写引擎，不内建距离、角度概念。欧氏几何、双曲几何、集合论、类型论全都是可加载的“公理系统包”。⊥ 的行为也由公理包定义，非经典逻辑公理包可重定义否定语义和矛盾推导行为，内核仅保留默认实现（直觉主义 ⊥）。
可演进
公理系统可升级，定理可固化为新规则，工程可在不同公理系统间迁移。最终，Lv-00 能用自身描述自身，成为自举的数学元语言。
自举的自我修改边界：C 引导核在自举成功后永久冻结——它在物理上不可被几何层的任何操作修改。几何层可以在抽象阶梯上无限演化（修改逻辑规则、编译策略、重写引擎的几何层编排），但所有几何层操作最终都必须通过冻结的 C 引导核 API 执行。Lv-00 是“终极数学构造沙盒”而非“自我进化的几何生命”——它可以在沙盒内无限制地演化，但沙盒的墙壁不可穿透。

三、计算与证明的统一机制
3.1 关联几何内核
C 内核仅维护五项基本关系：
· 关联（Incidence）：点在线上、线过点、点在区域边界
· 之间（Betweenness）：点在线段上、点在两点之间
· 相交（Intersection）：线与线相交、线与区域边界相交
· 包含（Containment）：区域包含点、区域包含区域
· 连接（Connection）：端口与端口相连
连续拓扑的缺失边界：五项基本关系处理的是离散的几何关系——点、线段、区域的静态拓扑。连续变形（同伦、同痕、连续映射）不在其原生表达范围内。原因：同伦等价所需的连续函数空间远超二次代数求解器的能力，且引入不可判定性；将其加入内核将破坏公理中立性（连续统假设独立于 ZFC，内核不应偏向任何连续模型）。连续拓扑目前被视为公理包层的高阶函数块编码问题——例如同伦可被编码为接受两个连续空间和一个参数化路径区域的函数块，其内部由公理包定义的构造子处理。未来若需引入原生支持，将作为内核的显式扩展并承担相应的理论代价（可判定性重新评估、公理中立性审查）。端口抽象机制已为其预留了空间。
连接的附属规约——端口归属标记与 namespace_depth 生命周期：
每个端口在创建时维护三个轻量字段：
· namespace_depth（整数）：该端口直接所属函数块的嵌套深度，画布全局为 0。
· parent_block_id（整数）：该端口直接所属函数块的唯一标识。全局画布端口此值为 -1。
· is_formal_param（布尔）：在该端口所属块内部，是否为形式参数（输入端口）。
这三个字段共同为复制操作提供 O(1) 的变量捕获判定基础（详见 8.1 节端口继承规则）。
四大原子操作中 namespace_depth 的维护：
1. 创建全局节点：depth = 0，parent_block_id = -1，is_formal_param = false。
2. 定义函数块（打包 PackFunction）：选定内部子图，指定输入/输出端口。
   · 选为输入/输出端口的节点保留在原上下文深度，作为函数块对外的接口。
   · 内部节点深度在块内重新基化：相对块深度 = 原深度 - 原上下文深度。块的内基准深度为当前上下文深度 + 1。
   · 内部端口的 parent_block_id 更新为该新函数块的 ID。输入端口 is_formal_param = true，其余为 false。
3. 函数应用（例化展开 Instantiate）：复制函数块内部子图。
   · 所有复制件节点的深度 = 当前上下文深度 + 原节点在块内的相对深度。
   · parent_block_id 不变（仍指向原函数块，除非被重映射为新复制块的 ID，但判定仅需比较 parent_block_id 是否等于被复制块 ID）。
   · 形式参数端口在 β-归约时被实参替代，其 is_formal_param 在归约后的重连操作中设为 false。
4. 嵌套打包：深度自然递增，与上述规则完全一致。
核心不变量：任何端口 p 的 namespace_depth 始终等于从全局画布（深度 0）到该端口直接所属函数块的嵌套层数。此不变量在每次图编辑和重写操作后由内核自动维护。
端口标记一致性保障：
· 预防层：所有图编辑操作（包括用户通过图形界面的交互）必须通过内核 API（AddNode、PackFunction 等），API 内部保证三字段不变量。画布操作被转换为原子命令——不存在绕过 API 的直接内存修改。
· 检测层：内核提供调试模式一致性断言功能。它遍历所有端口，验证：端口的 namespace_depth 等于其 parent_block_id 指向的块的深度；形式参数端口仅存在于函数块边界；连接类约束的两端端口在同一或相邻层级；所有端口的 parent_block_id 指向有效块。此断言在每次 API 调用后可选择性触发（开发阶段和关键操作后启用，正式运行时可关闭以提升性能）。
距离、角度、平行、垂直等概念由公理系统包通过以上基本关系组合定义，以“约束模板”形式提供。
3.2 约束模板机制与信任边界
为避免用户级操作直接面对底层关联几何的节点爆炸，公理包将常用的度量概念封装为约束模板。
模板分级管理：
· 一级模板（原子度量）：由公理包开发者手写，定义距离、角度、平行等基本度量的关联几何展开。每个一级模板在装入内核前，必须通过模板正确性形式化测试集。
  测试集分层与信任锚定：
  · 出厂测试集（与内核一同发布）：由内核开发者手工编写，每个测试用例包含模板实例化参数、展开后的约束网络、目标度量的解析公式计算结果、以及手工判定的预期结果（通过/失败）。内核仅负责执行测试并比对，预期结果始终来自外部，打破“自验证”循环。
  · 用户测试集（公理包作者添加）：格式与出厂测试集相同，预期结果由公理包作者手工给定。内核在加载公理包时一并运行。
  · 一级模板通过全部测试后注册，其正确性由形式化测试担保，是内核可信基的延伸。
  模板展开正则形式强制：一级模板在通过测试集时，不仅验证“展开结果等价于目标度量”，还验证“展开结果符合该模板的正则形式规范”。例如：
  · “两点距离为 d”的模板规范：一条线段 AB，其 length 属性绑定为 d，且线段约束仅含 INCIDENCE 关系（端点与线段关联）。任何使用额外辅助点或更复杂约束组合的实现将被测试集拒绝。
  · “三点共线”的模板规范：三个点 P1、P2、P3，存在一条线段 L，三个点与 L 的 INCIDENCE 关系 + P2 在 P1 与 P3 之间的 BETWEENNESS 关系。
    这确保同一模板的所有正确实现产生相同的基本关系图结构，消除不同模板开发者的实现差异导致的匹配歧义。
· 二级模板（用户复合体）：用户在工程中定义的宏块。其信任依赖于一级模板的正确性，不需要内核级验证。
调试透明度：当用户需要检查涉及模板的约束冲突时，系统可提供“展开视图”——临时将模板实例展开为完整基本关系图，高亮冲突位置。日常交互中保持压缩态。
3.3 符号坐标与同一性判定
每个几何节点维护两类坐标：
· 符号坐标（真值源）：有理数、代数数（极小多项式+隔离区间）、命名超越常数（π, e 等）。代数数判等可判定（通过隔离区间细化与 Sturm 序列判定符号），超越常数仅在同名时判等。
· 数值近似坐标（显示层）：浮点数，仅供渲染和交互探索，不参与任何证明判等逻辑。
“两条线段重合”仅依赖符号坐标上的精确代数判等。
代数数工程优化——A/B 双轨技术选型：
A 计划（主轨道——基于现有库适配的完整代数数）：
· 有理数：使用 GMP（GNU Multiple Precision Arithmetic Library），成熟的任意精度有理数 C 库。
· 代数数：使用 SymEngine（C++ 符号计算库）或 FLINT（快速数论库）的代数数扩展，这些库已实现代数数的基本运算和判等。
· 核心工作：适配与集成——将这些库的接口封装到 Lv-00 的 SymbolicCoord 数据结构中，实现优先有理化通路和惰性精度管理。
· 前置压力测试：阶段一早期即对选定的库进行隔离压力测试，针对代数数运算链和判等获得真实性能基准和精度行为数据。明确 B 计划启动的精确条件：不可恢复的精度失真（如隔离区间收敛到错误根）、或性能急剧恶化（如单次判等时间超过阈值 100 倍均值）。
· 目标覆盖尺规可构造几何的全部代数需求（绝大多数 ≤4 次）。
B 计划（降级轨道——从零实现的有理数 + 命名二次根式）：
· 符号坐标仅支持：有理数（任意精度整数比，从零实现）、命名二次根式（以 sqrt(n) 形式存储，n 为无平方因子正整数）、上述二者的加减乘除组合（结果保持在二次扩张内或退化为有理数）。
· 二次根式的规范表示：a + b√n，其中 a、b 为有理数，n 为无平方因子正整数。乘除运算后归约到规范形式。判等直接比较 a、b、n 三元组。
· B 计划覆盖范围：所有尺规可构造点（尺规可构造数的代数特征恰好是二次扩张塔），欧几里得《几何原本》全书的命题。不可覆盖：正七边形边长、倍立方体等古典三大难题。
· 实现复杂度骤降（二次根式系统可在数周内完成），不涉及隔离区间，不涉及高次多项式判等。
评估与切换：阶段一前六个月为代数数开发窗口。A 计划基于现有库适配（GMP + SymEngine/FLINT），工作重心在集成而非从零实现。三至六个月内 A 计划需同时满足以下两个指标，否则无条件切换至 B 计划（代数数完整支持作为阶段二增强目标）：
· 指标一（精度稳定性）：隔离区间在连续 100 次运算后精度衰减不超过 1 bit。
· 指标二（性能稳定性）：单次运算链中，有理数中间结果的最大位数不超过 10^6 比特（约 30 万位十进制数字）。超过此阈值时触发位数熔断（详见下文）。
  若因许可问题、性能不达标或前置压力测试暴露不可恢复的精度缺陷导致集成遇阻，亦切换至 B 计划。
两种计划的接口统一，SymbolicCoord 的 type 枚举预留 QUADRATIC_RADICAL 值，确保切换时不需重写上层代码。
优先有理化通路：每次符号运算生成新代数数节点时，在完整代数数归约之前，先运行轻量级检测：
· 用连分式近似（或二分隔离）计算该代数数的一个有理近似值，精度略低于当前隔离区间。
· 将此有理数候选值代入极小多项式，在符号层（精确有理算术）计算多项式的值。
· 若值为零，则该代数数等价于此有理数——立即用有理数节点替换代数数节点，不再执行后续代数数归约。
  这将在实践中捕获绝大多数“本为有理数”的中间结果，将代数数节点的实际数量压缩到必需的最低限度。
隔离区间精度惰性管理：初始精度仅足以区分极小多项式的其他实根。更高精度仅在以下情况触发：
· 两个不同代数数判等时（精度需提高到足以判定不相等）。
· 用户请求数值显示时（按需提高精度）。
  多项式次数设软上限（建议 8 次），超限建议用户引入辅助构造或 oracle 块——大多数尺规可构造几何产生的代数数次数不超过 4。
位数熔断的传染阻断与冻结点回退：
当位数熔断触发时（中间结果位数超过 10^6 比特），系统执行以下保护措施：
1. 标记不自动传播：“数值辅助”标记不自动附着到依赖其计算出的后续节点上。当一个新几何节点需要基于“数值辅助”节点的坐标来计算符号坐标时：
   · 若运算完全在符号层可完成，系统尝试符号化简。若化简成功，新节点为纯符号。
   · 若运算必须依赖数值近似值来确定符号表达式，系统拒绝生成新节点，将该运算标记为“待完成的证明义务”（蓝色虚框），并提示用户当前步骤因上游熔断而阻塞。
2. 传染边界：一个“数值辅助”节点只能直接参与显示渲染和数值探针查询。任何试图将其作为构造步骤输入以产生新符号几何体的操作，在该节点的“数值辅助”标记被解除前，都被系统暂停。
3. 冻结点回退：触发时系统自动在触发操作前保存当前约束图的完整状态（冻结点）。用户收到熔断警告后，可选择：
   · 忽略：接受该节点为“数值辅助”，保留当前状态（含“数值辅助”节点及其中间操作），后续依赖该节点的构造步骤将被逐个阻塞，需用户逐个处理。这是“带技术债务继续前进”的路径。
   · 回退：恢复到冻结点状态，撤销从冻结点到熔断触发点之间的所有操作（包括中间产生的“数值辅助”节点），熔断被撤销。用户可插入辅助构造（如引入新的命名中间点、拆分复杂表达式为多步简单构造）来避免位数膨胀，然后重新执行。这是“全部撤销”路径。
     两种选择互斥，不存在“部分保留”的语义张力。
4. 永久降级为数值假设（逃逸出口）：当用户在同一位数熔断点上连续触发熔断达到阈值（默认为 3 次）时，系统在“忽略”和“回退”之外提供第三个选项：“永久降级为数值假设”。用户选择此选项后：
   · 该节点被永久标记为“数值假设（橙黄色）”。其语义是：该节点的精确值未被符号求解器验证，但被高精度数值近似（精度阈值由用户指定）所支持。
   · 该节点可正常参与后续构造，不再受传染阻断限制——后续节点可基于此节点的数值近似值进行正常构造，但所有依赖它的下游节点自动继承橙黄色标记。
   · 最终定理如果依赖任何橙黄色节点，其整体着色为“橙黄色（含数值假设）”——这比纯绿色（全构造）弱，但比蓝色（未完成）强。它表示定理在声明的数值精度下成立，但未在符号层完全闭合。
   · 用户须在签署此选项时提供一个“数值假设声明”文本，说明放弃符号严格性的原因和数值近似的精度阈值（例如“该点坐标在 10^{-15} 精度下近似为 1.414213562373095，对应 √2 的数值近似”）。此声明随证明一起存储，对审查者和读者可见。
这确保了熔断是一个可控的“施工暂停”，同时也为本质上无法避免位数膨胀的场景提供了诚实的逃逸出口——而非无限循环。
3.4 约束求解器
· 优先使用几何推理消元（相似三角形、勾股定理、平行线比例等定理），在符号坐标上产生多项式约束。
· 代数引擎求解（Gröbner 基、柱形代数分解的受限变体），结果始终为符号坐标。
· 覆盖范围：希尔伯特平面几何的线性、二次、比例片段——即尺规可构造片段的完整代数刻画。在此边界内保证符号解。
· 超出覆盖范围：标记为“待完成的证明义务”（蓝色虚框——“超出范围”），数值探针可供人工判断但不写入证明图。
· 增量求解：仅更新受新约束影响的子图。
“超出范围”后的辅助构造建议：求解器检测到超出二次范围时，可分析方程结构：
· 若方程可因式分解为多个二次因子，系统提示“可通过引入辅助线将问题拆分为多个二次步骤”，并高亮潜在的拆分点。
· 若方程为不可约三次（如正七边形边长的极小多项式），系统提示“该问题在当前公理包下可能不可构造，可尝试归约至已知不可构造问题”。用户可据此启动不可构造性证明模板。
3.5 不可构造性证明
当系统将某个构造目标标记为“待完成的证明义务”且用户无法找到任何构造路径时，该蓝色虚框可被进一步转化为不可构造性的几何证物。
蓝色虚框的子状态：
为区分“暂时不会”与“真的不可能”，蓝色虚框增设三个子标记：
· 蓝色（资源受限）：步数熔断或求解器超时触发。提示用户可尝试增加步数上限或优化构造。
· 蓝色（超出范围）：求解器报告问题超出其代数覆盖范围（如遇三次方程）。提示用户可尝试归约至已知不可构造问题。
· 蓝色（未探索）：默认状态，尚未主动穷尽构造空间。用户可触发构造空间穷举工具。
用户可对蓝色“未探索”触发构造空间穷举工具（如对尺规公理包下的有限组合路径进行自动尝试），将可能转化为黄色或绿色的不可构造性结论。
归约式不可构造性证明机制：
· 系统提供不可构造性证明模板——一个几何构造，其输入是目标问题（如“三等分角”），其输出是一个已知不可构造问题（如“倍立方”）的构造。
· 用户在模板内完成归约构造（使用当前公理包的全部许可构造子）。
· 若归约构造通过合一检查，且目标已知不可构造问题被公理包标记为“不可构造”，则蓝色虚框转为特殊的“已证不可构造”标记。
不可构造性依赖链的引用格式：
公理包中“已知不可构造问题列表”的每个条目可通过依赖链字段引用其依据来源。引用分为三种形式：
· 内引用：指向公理包内的一个引理块，记录该引理块的唯一标识符（公理包内命名空间下的块 ID）及其内容哈希。内容哈希仅基于约束图的规范表示（Canonical Graph Representation）计算：
  · 对约束图节点按拓扑序重新编号（规范标签基于 WL 图核的迭代标签）。
  · 仅序列化约束类型、节点类型、符号坐标的规范表达式（代数数以规范形式表示）。
  · 不序列化块名称、注释、视觉布局信息、节点 ID 等元数据。
  · 内容哈希通过 SHA-256 计算。
    加载时系统对引理块计算当前内容哈希并与存储值比对。内容哈希相同 → 数学内容未被修改，引用有效。内容哈希不同 → 数学内容已变化，触发降级。这一设计确保纯格式编辑、重命名等操作不会污染依赖链。
· 外引用：一个规范引用字符串，指向公认文献或形式化证明（如“Wantzel 1837”对三等分角的证明）。外引用被视为永久有效的形式化支撑，不参与自动重验。外引用可选附带“信任注释”——包含验证状态（如“截至 2025 年公认有效”）和时间戳，仅供审查者参考，不参与自动降级逻辑。
· 作者断言：引用字段为空或标记为“公理包作者断言”。系统立即将其识别为黄色基础。
依赖链断裂的自动降级：
公理包升级后，系统自动重验所有引理块并重新计算内容哈希。若内引用指向的引理块内容哈希变化（数学内容改变），依赖链断裂。此时：
· 降级规则：绿色结论若其依赖链中任一内引用断裂，自动降级为黄色“条件性不可构造——依赖已失效”。系统提示用户该结论需要重新验证。若断裂的引用后续被修复（用户手动重证了引理块，使其内容哈希再次匹配），则恢复绿色。
· 降级限域：降级不影响已完成的归约证明的合一检查结果——该归约构造本身仍然有效。降级只影响结论的着色与信任级别。
分级着色：
· 绿色“已证不可构造”：目标问题归约到列表中某条目，且该条目的依赖链追溯到形式化证明或公认数学定理，且所有内引用的内容哈希均匹配。
· 黄色“条件性不可构造”：目标问题归约到列表中某条目，但该条目仅由公理包作者断言，或依赖链中某个内引用内容哈希不匹配。
· 蓝色（子分类如上）：未找到任何归约路径，或尚未完成不可构造性分析。
3.6 图重写引擎
· 每条规则含匹配模式（带变量几何子图）和替换模式（更简单或等价的几何配置）。
· 匹配算法的局部等价容忍：匹配时，对于符号坐标相同但节点 ID 不同的两个点，匹配算法基于符号坐标判等执行一次轻量级的局部等价检查，无需全局调用图规范化遍。这避免了在每次重写前后触发规范化的开销，同时确保“结构相同但存在冗余节点”的配置可被正确识别。全局图规范化遍仅在一检查前和用户显式请求时执行。
· 协作协议：重写优先（新约束加入后先尝试所有可用规则） → 求解跟进（重写无法推进时调用符号求解器） → 冲突暴露（求解器检测到过约束冲突时高亮并暂停，请求用户介入）。
· 终止性控制：
  · 约简测度标记：每条重写规则应标记其“约简测度”（如节点数减少、代数次数降低）。有测度的规则优先应用，无测度的规则仅在用户显式触发时应用。
  · 全局步数计数器：整个重写+求解联合过程有步数上限（用户可配置），超限暂停并请求用户介入。
  · 图哈希循环检测：维护近期图的哈希摘要（基于 WL 图核的结构哈希，详见下文）。若在滑动窗口内出现重复图，暂停并报告可能循环。
· 汇合性：不保证全局汇合。核心公理包提供预验证汇合性的安全规则集——该汇合性证明由外部数学审查担保（通过 Knuth-Bendix 完备化等方法在系统外手工完成），随公理包文档发布，构成系统的第二可信基。
图哈希方案：哈希基于 WL（Weisfeiler-Lehman）图核的结构哈希。每个节点在哈希前被赋予一个基于其拓扑邻接关系的规范标签，迭代聚合邻居标签。哈希计算为 O(E) 时间复杂度，基于图结构而非节点 ID——结构相同但 ID 不同的图产生相同哈希。WL 哈希不能保证无碰撞（两个不同构的图可能碰巧哈希相同），但碰撞极低概率。即使发生碰撞，重写引擎会在后续步骤中发现无法匹配替换模式——这仅导致一次无效的重写尝试被回退，不威胁证明正确性。
汇合性与类型等价检查的可靠性保障：
由于全局汇合不保证，类型等价检查面临潜在风险。系统通过双层机制应对：
· 第一层：核心规则集汇合性担保。对于类型等价检查最关键的规则子集（区域等价化简规则），核心公理包的安全规则集已经过外部汇合性验证（第二可信基）。只要类型检查仅使用这些规则，范式唯一性被保证。
· 第二层：用户交互式路径探索。当自动重写无法将两个区域归一到同一范式时，系统不立即判定“不等价”，而是报告“未能证明等价”。同时提供交互工具允许用户手动选择重写路径、回溯、尝试替代规则。若用户找到一条使两者合一的重写路径，等价成立，该路径被记录并可回放。
· 风险边界：若用户引入自定义非核心规则且破坏了汇合性，等价检查可能漏判。引入自定义规则的汇合性责任由用户承担。
第二可信基审查辅助——关键对可视化器：
虽然汇合性审查由外部数学审查手工完成，但 Lv-00 将在公理包编辑器中提供“关键对可视化器”以大幅降低审查者出错率：
· 给定一组重写规则，编辑器自动计算全部关键对（critical pairs）——即两条规则的重叠应用可能导致歧义的项。
· 对每个关键对，生成两个几何图：分别沿两条规则归约一步得到的结果。将两个几何图并排呈现，并高亮它们不匹配的部分。
· 审查者通过视觉比对直接“看见”这两个归约结果是否等价。若等价（在安全规则集内可通过若干步安全规则相互转换），审查者确认该关键对汇合。若不等价，审查者看到冲突点，可手工添加新规则来弥合歧义。
· 此工具不自动证明汇合性，而是将非汇合性风险变得几何上可感知——审查者通过视觉比对发现歧义并通过添加规则或调整规约序来修复，这本身也是一种几何构造活动。
审查循环的极小可信基假设与管理：关键对可视化器隐含一个无法完全消除的信任循环——它的渲染器和结构比较逻辑必须正确。如果渲染器有 bug 或合一检查器有 bug，可视化器可能错误呈现关键对结果，误导审查者。Lv-00 对此的管理策略是：
· 双重确认：可视化器同时提供结构比较的文字报告（节点不匹配列表、约束缺失列表）和视觉呈现（并排图 + 高亮）。审查者被要求交叉验证两者——如果文字报告说“不等价”但视觉呈现看起来一样，说明渲染器有 bug，触发内核调试。
· 极小范围：渲染器的结构差异高亮逻辑是极简的图结构比对算法（与合一检查器使用相同的图结构匹配引擎），其正确性由内核测试执行器（< 数百行）担保。这个极小可信基被收缩到可人工审查的范围。
· 外部锚定——导出规范表示：在关键对可视化器中提供“导出规范表示”功能。对于每个关键对的两个归约结果图，生成两个独立的规范化文本文件——格式为标准化邻接表（节点类型 + 约束类型 + 符号坐标规范表达式）。这些文本文件可被外部独立图同构检查器（如 nauty/Traces）验证，也可被手工审查。审查工作流变为：
  1. Lv-00 可视化器呈现关键对并排图 + 文字报告。
  2. 审查者视觉检查并排图，阅读文字报告。
  3. 如有疑虑，审查者导出两个规范文本文件，使用外部工具（如 nauty）进行独立验证。
  4. 审查结论基于“可视化器报告 + 外部验证”的双重确认。
     这彻底打破了审查循环——外部工具不必信任 Lv-00 的任何实现，它只进行图同构检查。信任根被锚定在独立的外部工具链上，而不仅仅是 Lv-00 自身的匹配引擎。
此工具计划在阶段三或阶段四的公理包编辑器增强中实现。
3.7 函数块与确定性
· 函数块内部是受保护约束子图，带输入端口（开放圆环）和输出端口（实心圆）。
· 封装时确定性检查（分层判定）：
  · 静态层（打包时）：对内部约束图执行快速静态分析。对线性约束系统，解的存在唯一性可多项式时间判定。对二次系统，使用符号代数引擎尝试消元并计算解的个数。若在步数上限内完成且确认为唯一解，函数块标记为“已验证唯一性”，封装通过。
  · 动态层（打包时未完成静态分析）：若静态分析未能在步数上限内确认但未发现冲突，不阻止封装。函数块标记为“未验证唯一性”，允许使用。在每次函数应用时，求解器计算具体输出：
    · 若产生唯一解，正常输出。
    · 若产生多解且用户未提供选择器，函数应用被拒绝并提示“该函数在此输入下产生多解，请提供选择器（如‘取正根’）”。
    · 若产生零解，报告“无解——输入不满足前置条件”。
  · 这避免了“长期卡在确定性检查中”的问题——未验证的块可被使用，但当多解实际出现时才要求用户介入。
· 多解选择器：用户可为函数块预提供选择器（如“取正根”、“取位于区域 A 内的解”），或在实际多解时即时指定。选择器成为函数块定义的一部分。
· 无解语义：无解 = 输入不满足函数的前置条件。系统支持用户声明前置条件区域（一个几何区域），不满足时函数应用在合一检查阶段即被拒绝并高亮。
· 函数应用：实参接入 → 内部复制展开绑定 → 符号求解器计算输出（若能确定唯一解）或触发选择器/报告无解。
打包时的跨边界约束检查：
当 PackFunction 将内部子图封装为函数块时，内部节点从全局可访问变为“封装”。内核在打包操作执行前强制检查所有非连接类约束（关联、之间、相交、包含）是否涉及内部端口与外部节点的跨边界关系。检测逻辑：
· 遍历所有约束，检查其参与者是否同时包含内部节点（即将被封装的节点）和外部节点（不在打包范围内的节点）。
· 连接类约束（CONNECTION）不受此限制——端口连接在封装后自动被函数块边界端口接管。
· 若存在跨边界的非连接约束，系统弹出打包冲突对话框，列出所有涉及的约束，并提示“以下约束将被函数块边界遮蔽”。
用户对每个跨边界约束逐条选择：
· 提升：将该约束提升为函数块的端口依赖。该约束成为函数块输入或输出规约的一部分，外界可见并参与合一检查。
· 断开：删除该约束。用户确认在封装后此约束不再需要。
· 取消：放弃本次打包操作，返回编辑状态，用户可重新调整内部构造后再打包。
跨边界约束提升的几何表示：提升后的约束在函数块的端口附加属性槽中存储。在函数块外壳上，这些约束以图标或缩略几何图形附着在对应端口旁：
· 包含约束：端口旁显示小圆含小点的图标。
· 关联约束：端口旁显示短线穿过点的图标。
· 之间约束：端口旁显示三点一线的小图标。
  这些可视化标记仅承载信息，不改变端口连接的行为。在文本模式中，它们对应函数签名的附加条件（类似依赖类型中的前置条件断言）。当函数块被应用时，这些提升的约束作为被应用函数的附加前提参与合一检查。
3.8 命题、证明与合一检查
· 命题：虚线框起的几何模式，含输入/输出端口。命题声明了“什么样的构造能被接受为证物”。
· 证明：在命题框内进行许可的几何构造（仅使用当前公理包定义的构造子和约束模板）。
· 正确性判据（合一）：构造的外部端口与命题模式在合一算法下精确匹配。
图规范化遍：在合一执行前，系统对构造图和命题模式图各执行一次轻量级的图规范化遍（Graph Normalization Pass）。规范化操作仅限于基于内核符号坐标判等的机械合并：
1. 遍历所有点节点，若两个点的符号坐标经内核判等确认为完全相等（代数数判等为真），则检查其作用域归属。若两个点属于同一作用域（相同的 parent_block_id 和相同的 namespace_depth），自动合并为一个规范节点——保留其中一个，将所有引用另一个点的约束重定向至保留的节点，移除冗余节点。若两个点属于不同作用域，系统提示用户确认是否合并，用户可选择合并、保留两者（不合并）或取消此次规范化。
2. 对线段和区域节点同理——若两端点/边界符号坐标完全相同，合并冗余节点。
3. 合并后，对约束图进行拓扑排序稳定化，产生唯一的规范化结构。
   此规范化仅基于可判定的符号坐标判等，不涉及任何公理包定义的等价关系（如三角形的 SAS 全等判定），不调用约束求解器。规范化步骤在证明导航器中作为“自动规范化”记录，用户可展开查看规范化前后的图差异——合并的冗余节点以灰色虚影显示，保留的节点以高亮显示。
规范化后的构造图和命题模式图进入标准合一流程，匹配包含三个层面：
1. 端口类型匹配：构造的输入/输出端口类型与模式声明的端口类型一致。
2. 约束类型匹配：构造中的每个约束的类型与模式中对应约束的类型一致。当模式包含约束模板实例时，先将模板展开为正则形式的基本关系图，再与构造中的实际基本关系图进行图结构比较。
3. 符号坐标判等：约束的参数符号坐标在代数判等下等价。
   三者全部满足，合一成功，虚线变实线，命题得证。图形闭合是匹配成功的副现象。
合一语义的严格边界：合一被严格定义为含图规范化遍的图结构匹配，不引入约束可满足性等价。理由是：任何语义等价但结构不同的构造（例如用不同辅助线表示的同一几何事实），需要用户显式通过重写规则化简才能匹配——这是“证明步骤必须显式”的构造主义要求。系统不在合一中隐式调用约束求解器来判定语义等价。图规范化遍仅在符号坐标严格相等且属同一作用域（或跨作用域经用户确认）时合并节点，不跨越结构差异。
合一严格性的实用缓解：核心公理包提供安全重写规则集（含交换律、结合律、对称律等常见等价关系），这些规则被汇合性证明担保。重写引擎在步数上限内自动应用安全规则将构造化简到范式——用户无需手动处理常见等价。图规范化遍进一步降低了手动处理“两个点坐标完全一样所以应该合并”这类纯机械操作的需求——安全规则集因此可以缩小，无需覆盖坐标判等驱动的平凡等价。
· ⊥ 的公理包可定义性：⊥ 不是全局硬编码节点，而是公理包可定义的命题模式。公理包在定义命题与证物协议时，可指定以下三项：
  · ⊥ 的几何表示：默认实现为无可填充端口的空模式——一个仅有输入端口（接受证物 A）而无输出端口的几何模式。任何带有输出端口的构造试图与 ⊥ 合一必然失败（无可匹配的输出端口）。
  · ¬ 的编码：默认实现为 A → ⊥（标准 BHK 解释）。公理包可覆盖为其他几何编码（如经典逻辑中 ¬A 可定义为 A → False 的特定几何变体）。
  · 矛盾推导行为：当系统在某分支中推导出 ⊥（即构造出 A → ⊥ 的证物且 A 也得证）时，默认行为是阻塞进一步推导（对应直觉主义逻辑——从矛盾不能任意推导）。公理包可覆盖此行为，指定爆炸原理规则（ex falso quodlibet）——从 ⊥ 可推导任意命题 P 的几何构造。
  · 非经典逻辑公理包加载提示：当公理包覆盖了 ⊥ 的默认定义或矛盾推导行为时，系统在加载时提示“该公理包使用了非标准否定语义”，提醒用户注意其逻辑假设。
  · 内核保留默认实现（直觉主义 ⊥），但允许公理包在加载时覆盖。这保持了内核的公理中立——⊥ 只是一个“可由公理包配置的矛盾标记”。
爆炸原理的构造主义代价与可追溯性：若公理包定义了爆炸原理，系统在块库中提供一个预置的“爆炸原理函数块”——输入端口类型 = ⊥，输出端口类型 = 可变的 P。该块的内部不是空的，而是包含一个特殊的标记节点：“ex falso quodlibet”。当该块被例化时，系统在证明图中显示一个从 ⊥ 到 P 的浅橙色虚线箭头，并标注“爆炸原理应用”。此步骤在证明导航器中作为单独步骤被记录。它与非构造性 oracle 块依赖（使用浅橙色实心端口标记）在视觉上有所区分——前者是浅橙色虚线箭头（局部推理规则），后者是浅橙色实心端口标记（全局假设依赖）。证明导航器的图例中明确列出这两种浅橙来源的区分。
非构造性公理的包覆立场：对于选择公理（AC）、排中律（LEM）等非构造性公理，Lv-00 的立场是“容忍并包覆，而非吸收为构造”。公理包可声明非构造性 oracle 块——其输入端口为空（零元函数），输出端口为特定命题的证物，内部不包含任何几何构造。依赖此类 oracle 块的证明分支在依赖导航树中显示为特殊的浅橙色实心标记“依赖非构造性公理”。整个证明的最终着色不是纯粹的绿色（全构造），而是浅橙色（含非构造性 oracle 依赖）。系统不拒绝这类证明，但诚实告知信任前提。
数值假设（橙黄色）标记：当用户在位数熔断后选择“永久降级为数值假设”，该节点及其所有下游依赖节点被标记为橙黄色“含数值假设”。整个证明的最终着色为橙黄色（含数值假设）——表示定理在声明的数值精度下成立，但未在符号层完全闭合。此标记可与非构造性依赖（浅橙色）叠加，叠加后显示为深橙色。
颜色编码体系总结：
· 绿色：全构造，无任何非常规依赖。
· 蓝色（三子类）：待完成的证明义务。
· 绿色实框：已证不可构造（有形式化支撑）。
· 黄色虚线框：条件性不可构造（依赖作者断言或依赖已失效）。
· 浅橙色（实心端口标记）：依赖非构造性 oracle 块（选择公理、排中律）。
· 浅橙色（虚线箭头标记）：包含爆炸原理步骤。
· 橙黄色：含数值假设（位数熔断后永久降级）。
· 深橙色：同时依赖非构造性 oracle 和数值假设，或同时含爆炸原理和数值假设。
· 类型等价检查：端口连接时（编译期），重写引擎使用核心安全规则集（受汇合性担保）尝试将两个类型区域重写为同一范式。若成功则连接有效；若失败则报告“未能证明等价”并开放交互式路径探索（用户可手动选择重写路径、回溯、尝试替代规则）。
3.9 量词操作原语
· ∃-消去（解包）：存在量词块提供“证物端口”和“延续端口”。用户提供延续函数块（其输入接证物端口，输出接后续构造）。系统复制存在块内部构造，将证物端口接入延续块的输入，延续块的输出接后续证明步骤。
· ∀-消去（应用）：与普通函数应用完全一致。∀x.P(x) 是一个函数块，实参 t 接入输入端口，输出为 P(t) 的证物。
· 深层量词交替：通过函数块嵌套自然体现。嵌套深度过深时可折叠管理复杂度。
3.10 递归与条件
· 递归：构造可引用自身（在函数块内部引用该函数块自身的端口）。每个递归构造块必须声明测度——一个几何量及其上的良基关系（如线段长度、区域面积、嵌套深度等）。每次递归调用时求解器检查测度严格递减。测度类型可由公理包扩展。
· 条件：基于几何包含关系（点在区域内/外）控制选择器块。选择器块有两个分支子图，根据包含关系的实际判定结果，激活匹配的分支（实线），另一分支保持虚影（灰色）。
测度可判定性的隔离：
为防止“递归检查递归”的无限循环，测度的递减性判定严格分为两条隔离路径：
· 符号测度（内核路径）：测度是可归约到符号坐标上的几何量——线段长度、区域面积等由代数表达式给出的量。递减性判断由内核的符号代数不等式引擎直接完成（比较两线段长度值的大小，或两区域面积的代数表达式大小），不通过任何公理包的构造子。这是 O(1) 或多项式时间的代数判等/不等式判定。
· 非符号测度（模板路径）：公理包可定义无法归约为代数表达式的测度（例如在特定公理系统下定义的抽象序结构）。此类测度的递减性检查必须由公理包的一级模板以硬编码方式提供——模板展开为等价的基本关系图，由内核求解器执行该展开后的图结构的递减性判断，不进入通用求解器的构造子调用。
· 加载时检测：公理包在注册非符号测度类型时，需在模板元数据中声明“非符号测度比较器”。系统在模板形式化测试阶段验证声明与实际行为是否一致——测试集包含对测度模板的递减性验证用例，预期结果由公理包作者给定，求解器执行并比对。若声明为符号测度但展开后间接调用了通用构造子，在实际运行中会被步数熔断捕获（意外触发了重写或求解循环）。
· 内核提示：系统在加载公理包时，若检测到某测度被标记为“非符号测度”，则提示用户“该测度的递归终止性依赖公理包作者的模板正确性”。
四、双模态交互
两个完全等价的操作界面：数学语言文本和直接几何制图，共享命令日志和约束图。
文本模式：声明式数学语言，实时解析为原子命令（AddNode、AddConstraint 等），图形在画布上同步生长。
图形模式：鼠标/触控直接作点、连线、画区域、施加约束。框选构造可打包为函数块，文本侧同步生成对应定义。
同步协议：底层命令日志是唯一真相源。文本和图形操作都转为同构的命令序列。撤销和重做跨模态统一。同一几何关系的不同表示（如直角符号和垂直文字描述）被归一化为规范约束类型。
学习辅助：几何体可附带半透明文字标签作为学习辅助。标签不参与计算，可随时开启/淡化。系统不强制纯形态辨识——保留标签作为可选辅助系统。
探针与调试：
· 绿色：完全约束；灰色：有自由度；红色：冲突。
· 蓝色虚框（悬停显示子状态——未探索/资源受限/超出范围）：待完成的证明义务。
· 绿色实框：已证不可构造（有形式化支撑，依赖链内容哈希完整）。
· 黄色虚线框：条件性不可构造（依赖作者断言或依赖已失效）。
· 浅橙色实心端口标记：依赖非构造性 oracle 块（如选择公理、排中律）。出现在端口边框、依赖导航树节点中。
· 浅橙色虚线箭头标记：包含爆炸原理步骤。出现在证明步骤连线和导航器记录中。
· 橙黄色标记：含数值假设（位数熔断后永久降级）。出现在节点外壳、依赖导航树节点、证明步骤中。
· 深橙色标记：非构造性依赖与数值假设叠加。
· 图形无法闭合或合一失败时，系统高亮所有相关约束链，提供“冲突路径图”。
· 对未完成的证明义务，数值探针提供近似值但明确标记“未完成”。
· 证明导航器图例中明确列出所有颜色标记及其语义区分（浅橙色实心 vs. 浅橙色虚线箭头等）。
打包冲突对话框：触发打包操作时，若存在跨边界约束，弹出对话框列出所有约束及涉及的端口。每条约束提供“提升”（成为函数块端口依赖，外壳显示图标）、“断开”（删除约束）、“取消”（放弃打包）三个选项。用户逐条处理后打包继续。
爆炸原理步骤的视觉呈现：当爆炸原理函数块在证明中被例化时，从 ⊥ 的证物端口到目标命题 P 的输出端口之间显示一条浅橙色虚线箭头，箭头中段带有标记“ex falso”。在证明导航器中，此步骤被记录为独立步骤并标注其非构造性性质。与非构造性 oracle 依赖（浅橙色实心端口标记）在视觉和图例中明确区分。
数值假设声明的呈现：当用户在位数熔断后选择“永久降级为数值假设”，系统弹出数值假设声明对话框，要求用户输入：
· 数值精度的阈值（如 10^{-15}）。
· 放弃符号严格性的原因简述。
  此声明以注释块形式附着在受影响的节点上，并随证明一起存储。在证明导航器与依赖导航树中，该节点显示橙黄色标记并附带声明预览。
图规范化遍的呈现：在证明导航器中，合一前的自动规范化步骤作为“自动规范化”步骤被记录。用户可展开此步骤查看规范化前后的约束图对比——规范化合并的冗余节点以灰色虚影显示，保留的节点以高亮显示。跨作用域的合并确认提示以对话框形式呈现。

· 打包跨边界约束检查与提升机制
· 递归测度可判定性隔离（符号测度由内核不等式引擎直接判定，非符号测度由模板硬编码并提供加载时提示）
· 图规范化遍引擎：基于符号坐标判等的约束图轻量规范化（合并坐标相同节点，作用域感知提示；仅在合一前和用户显式请求时执行；重写引擎使用局部等价容忍匹配，不依赖全局规范化）
· 绝对冻结的引导核：C 引导核在自举成功后进入永久冻结状态。其在物理上不可被任何几何层操作修改——引导核的 API（AddNode、AddConstraint、合一检查、图规范化遍等）是只读服务接口，几何层可在抽象阶梯上无限演化，但最终所有操作必须通过这些冻结 API 执行。内核不参与 β-归约、重写或任何几何层的动态变换
内核组件可验证性优先原则：每个内核组件设计为输入输出可预测的纯函数，便于独立测试。测试执行器保持极小体积（< 数百行），只做“执行操作→比对预期”，预期由外部手工锚定。合一算法额外由核心公理包烟测集在加载时验证——烟测集包含已知应成功和应失败的合一用例（含经图规范化遍后应匹配的用例），预期由公理包作者根据其数学知识手工给定。

公理包加载时烟测：公理包可选择附带 smoke_tests.lvz 文件，内含正向烟测（该公理系统下应成功的简单构造）和负向烟测（应被拒绝的构造）。烟测执行享有独立保护：
· 独立步数上限：每个烟测用例的重写和求解步数上限为全局默认上限的 1/10（或单独配置值）。超限则该用例标记为“未完成”。
· 烟测总时间上限：整个公理包的烟测集执行总时间上限为 30 秒（可配置）。超时则剩余用例标记为“未运行”。
· 加载策略：烟测集中若有任何用例“超时”或“未运行”，系统发出警告但仍允许加载公理包——烟测是辅助检测工具而非阻塞条件，其失败不代表公理包矛盾。用户可手动重新运行烟测或忽略警告。未附带烟测集的公理包不强制要求，系统提示“该公理包未附带烟测集”。
非经典逻辑公理包加载提示：当公理包覆盖了 ⊥ 的默认定义或矛盾推导行为，或包含非构造性 Oracle 块时，系统在加载时提示：
· 覆盖 ⊥ 或矛盾推导行为：“该公理包使用了非标准否定语义”
· 包含选择公理/排中律 Oracle：“该公理包包含非构造性初始证物，依赖其的证明将携带浅橙色实心端口标记”
· 包含爆炸原理：“该公理包包含从矛盾推导任意命题的规则（explosion），依赖此规则的证明步骤将携带浅橙色虚线箭头标记”

六、类型系统与宇宙层级
6.1 宇宙层级机制
默认启用良基宇宙层级：基本几何体（点、线段）属第 0 层，由基本几何体构成的类型区域（如所有线段的集合）属第 1 层，区域只能包含严格低于其层级的几何体。层级检查在公理包层实现——作为公理包定义的有效性规则的一部分。非良基集合论公理包（如 Aczel 反基础公理）可关闭层级检查，代之以解引理等非良基相容性约束。内核保持本体论中立——它不强制层级，只提供几何基础设施。
6.2 非良基模式下的循环包含处理
关闭层级检查后，约束图中可能出现“区域 A 包含区域 B，区域 B 包含区域 A”等循环包含结构。这些结构在几何上对应非良基集合，是合法的数学对象。
· 对求解器的影响：包含关系是图拓扑关系而非代数方程，不增加求解器的代数变量或方程次数。
· 对终止性检测的影响：图哈希循环检测关注的是重写过程中图结构是否重复出现。循环包含是静态拓扑中的环，不必然导致重写的无限循环。
· 风险边界：若用户定义的规则沿包含关系无限展开，步数熔断介入。
6.3 多态与依赖类型
· 多态类型：函数框中包含可替换的类型区域（虚线框）。传入具体类型时自动适配。
· 依赖类型：输出类型区域由输入值通过确定构造给出，类型等价在端口连接时通过图重写判等完成（编译期）。
七、高维结构的几何表示与交互
7.1 核心原则
系统诚实地承认二维画布的物理限制。高维结构（四维及以上的乘积类型、高阶态射等）不以直接二维图形表示，而通过端口抽象块承载。二维矩形编码仅为投影视图之一。
7.2 投影机制——单向保真原则
每个高维抽象端口块强制附带用户可自定义的二维投影视图：
· 投影声明：用户指定维度映射规则——哪些高维坐标轴映射到画布 X、Y 轴，其余维度折叠或丢弃，构成确定的映射函数。
· 单向保真：投影中可见的任何几何关系在底层结构中必然成立。若底层关系的某种几何表现无法在当前投影中忠实表达，系统强制隐藏该关系，绝不允许假阳性显示。
· 元数据标注：被折叠维度的信息以淡色标注提示。
· 投影切换：用户可快速切换预设投影视角。
高维证明的信任锚点：在投影视图中，用户无法“看见”底层结构全貌，但每次端口连接操作都对应底层的图结构匹配（含图规范化遍）。正确性信任因此从“视觉直觉”迁移至“端口连接操作严格保真”。
7.3 语义缩放
通过语义缩放进入高维块的“内部透视”——当前画布上下文切换为以该块为主视角的局部坐标系，高维结构被投影展开。离开该块则回到上层视图。

1. C 实现内核：关联几何引擎、符号坐标、符号代数求解器、图规范化遍引擎、重写引擎（含局部等价容忍匹配）、基本前端。这是不可消除的第一可信基。自举成功后 C 引导核永久冻结——其 API 为只读服务接口，物理上不可被几何层修改。

8.1 λ-演算几何表示技术路线（可行性原型）
λ-抽象的几何表示：
· λx. M 表示为一个标准的 Lv-00 函数块。
· 其输入端口对应形式参数 x，在块内部产生一个几何体代表“x 的出现”。
· M 本身是一个几何构造，其中所有对 x 的引用都是连接到该输入端口的线段。
· α-等价在几何编码中自然退化：两个仅在变量名上不同的 λ-项，其端口连接图结构完全相同。
β-归约的几何对应：
· 函数应用 (λx.M) N 的几何配置：λ 块的输出端口连接到应用结构的输出位置，同时 N 的输出端口连接到 λ 块的输入端口。
· β-归约规则识别此特定模式：
  · 匹配模式：一个函数块的输入端口直接连接到另一个块（实参 N）的输出端口。
  · 替换操作：复制函数块内部的子图，将所有连接到 x 输入端口的连线重定向到 N 的输出端口，然后移除外层函数块和应用对接结构。
变量捕获的几何消解——基于 parent_block_id 的端口继承规则：
复制函数块内部子图时，对于每条被复制的连线，检查其目标端口 p：
· 情况 A（形式参数引用）：p.parent_block_id == 被复制块ID 且 p.is_formal_param == true。重定向到实参 N 的输出端口。
· 情况 B（自由变量引用）：p.parent_block_id != 被复制块ID。保持原目标不变。
· 情况 C（内部局部引用）：p.parent_block_id == 被复制块ID 且 p.is_formal_param == false。重映射到复制件对应新端口。
· 此判定为 O(1) 整数比较。
性能考虑：
· 惰性复制（写时复制）：复制操作不立即深拷贝整个子图，只在被修改时才真正复制被修改的节点和连线。
· 共享子图：多次归约共享静态结构引用，只在 β-归约直接影响到的路径上执行真正复制。
· 默认惰性归约：仅在需要合一检查或显示时才完全归约到范式。
共享子图写时复制的一致性保障：
· 安全共享条件：一个子图 S 可在多条归约路径中安全共享，当且仅当 S 是纯静态结构——内部不包含任何将被活跃 β-归约影响的形式参数引用。
· 单线程惰性归约下的正确性：同一时刻仅有一条归约路径处于活跃状态，修改时机严格串行化。
· 并发归约下的扩展注意：若未来引入并行归约，需引入归约作用域 MVCC，作为自举后增强。
深度压力测试用例：
测试一：Church 数字 2 的乘幂 (2^2) 完整归约迹——验证同一 Church 数字函数在反复写时复制下的一致性。
测试二：Y 组合子单步展开 Y F → F (Y F)——验证自引用端口的 parent_block_id 在复制展开后正确传递。
测试三：Y 组合子多步归约 Y F 3 至范式（6 = 3!）——验证深层递归展开中共享子图在多次部分修改、部分共享下的引用一致性。
长期稳定性测试（阶段四）：对 Church 数字多次运算循环执行，监控内存使用和节点计数，确认无引用计数泄漏。调试模式提供“子图引用计数校验”功能。
核心重写迹示例：
示例一：(λx.x) y → y
1. 初始配置：λx.x 内部仅一条从输入到输出的连线。应用 (λx.x) y 将输入端口与 y 输出端口连接。
2. 模式匹配：检测到函数块输入端口连接到 y 的输出端口，触发 β-归约。
3. 替换执行：复制内部子图，连线目标为形式参数（情况 A），重定向至 y 的输出端口，移除外层函数块。
4. 结果：y 的输出端口直接对接。归约完成。
示例二：(λx. (λy. x)) z → λy. z
1. 初始配置：外层块 λx.(...) 包含内部块 λy.x。内部块有输入端口 y（parent_block_id 为内部块 ID）和对 x 的引用（parent_block_id 为外层块 ID）。外层块输入端口连接 z。
2. 模式匹配：检测到外层块输入端口连接到 z 的输出端口，触发外层块 β-归约。
3. 替换执行：
   · 指向 x 的连线：parent_block_id 等于被复制块 ID（情况 A），重定向至 z。
   · 指向 y 的连线：parent_block_id 为内部块 ID ≠ 被复制块 ID（情况 B），保留原目标。
   · 内部块输入端口 y：属于情况 B，复制后保持不变。
4. 结果：得到新块 λy.z，z 正确替换 x，y 未被错误绑定。
8.2 命题逻辑验证器的几何语义（BHK 几何编码）
核心原则：在 Lv-00 的“构造即证明”框架下，命题逻辑的语义自然地遵循 Brouwer-Heyting-Kolmogorov（BHK）解释的几何化——一个命题为真当且仅当存在一个证物构造，其外部端口与命题的几何模式合一（含图规范化遍）。
逻辑连接词的几何表示：
· ∧（合取）：乘积类型 A×B 的函数块。接受两个证物，输出元组区域。
· ∨（析取）：和类型 A+B 的函数块。接受一个证物，输出带标记的析取证物。
· →（蕴含）：标准函数块 A→B。
· ¬（否定）：默认定义为 A → ⊥，其中 ⊥ 的意义由公理包定义（默认：无可填充端口的空模式）。公理包可覆盖。
· ⊥（矛盾）：预定义的命题模式，其行为由公理包指定。默认：无输出端口的空模式。
验证器的工作流程：
1. 输入：一组前提命题的几何模式和一个目标命题的几何模式（虚线框，等待填充）。
2. 推理过程：验证器尝试将前提证物通过函数应用和函数块打包逐步组合，向目标命题的几何模式逼近。
3. 成功条件：最终构造经图规范化遍后，其外部端口与目标命题模式在合一算法下精确匹配。
4. 失败条件：系统报告“未能证明”，或构造被识别为归约到 ⊥（若公理包定义了爆炸原理，则从 ⊥ 可推导任意命题，但此步骤携带浅橙色虚线箭头标记）。
烟测验证方式：
· 正向烟测：提供一个经典真值表中为真的命题及一组前提（如 prove(P → Q, P) ⊢ Q），验证器应能产生与目标模式合一的构造。预期结果由公理包作者手工给定（应为“成功”）。
· 负向烟测：提供一个经典真值表中为假的命题及一组前提（如 prove(P → Q, ¬P) ⊢ ¬Q），验证器应无法产生合一的构造。预期结果由公理包作者给定（应为“失败”或“不可构造”）。
· 信任根：烟测的预期结果来自外部知识（经典真值表），由公理包作者手工给定。烟测执行器仅比对“验证器报告成功/失败”与“预期成功/失败”。不存在循环信任。
· 边界：烟测不验证验证器的内在完备性，只验证“在应该成功时成功、在应该失败时失败”的生效性。

13.5 各机制自洽性确认
· 图规范化遍仅基于符号坐标判等合并冗余节点，作用域感知，不调用约束求解器，仅在合一前和用户请求时执行。重写引擎使用局部等价容忍，不依赖全局规范化。
· 降级只修改 trust_color，不影响几何图结构。

· 合一检查先调用图规范化遍（只读），再执行图结构匹配。

· 所有机制响应域隔离，无循环依赖。
十四、总结与元理论立场
Lv-00 是一张永远展开的几何画布，定理变成形状，证明变成看得见的重合，程序变成沉默却不容置疑的图形。它不信仰任何数学真理，却可以为一切真理提供几何肉身。
双重模态定位：Lv-00 在两个模态下运作。在可被直观几何化的数学片段中，它提供真正意义上的“看得见的正确性”——拼图的严丝合缝本身就是正确性的几何事实。当数学对象的抽象层级超出二维几何直觉时，它提供统一的几何操作语法而非直接的几何直觉——端口连接成为主要交互载体。Lv-00 不对所有数学强行承诺几何直观——它只在几何直觉自然可及的范围内提供直观，在所有范围内提供统一语法。
信任根层级：
· 第一可信基：C 实现的关联几何内核，体积目标数千行。自举成功后永久冻结。
· 第二可信基：核心公理包安全重写规则集的汇合性证明，由外部数学审查担保。审查者可借助关键对可视化器的三重确认（视觉呈现+文字报告+外部规范表示导出），锚定到独立外部工具链。
· 模板可信基：一级约束模板通过双层形式化测试集验证，预期结果由外部手工锚定。
信任模型：与传统形式化系统（如 Coq）本质相同——信任基础极小但不可消除。
公理中立的精确范围：内核仅维护五项基本关系、图规范化遍、端口归属标记，不承诺任何度量结构，不硬编码 ⊥。各类逻辑与集合论以平等的 .lvz 公理包形式承载。连续拓扑不在当前内核范围内。
正确性判据：锚定在“含图规范化遍的图结构匹配”上——图规范化遍仅基于可判定的符号坐标判等合并冗余节点，作用域感知，不牺牲构造主义严格边界。重写匹配局部等价容忍避免规范化与重写的交织。安全重写规则集范围缩小至高阶等价。这一判据在可构造范围内提供“看得见的正确性”；在抽象边界上，信任迁移至端口连接严格保真；Lv-00 的价值转变为操作统一性。
“操作统一性能否在实践中降低高维数学建模的心智负担”这一假说，被明确标记为待验证的经验问题，将在 Lv-00 自举后的人因评估中作为核心度量指标接受检验。
不可构造性的诚实边界：蓝色虚框三个子状态 + 依赖链内容哈希引用 + 自动降级。内容哈希忽略元数据，格式编辑不触发降级噪音。外引用可附信任注释供审查者参考。
非构造性片段的包覆立场：非构造性 oracle 块（浅橙色实心端口标记）、爆炸原理（浅橙色虚线箭头标记）、数值假设（橙黄色）通过多色标记系统强制可见，浅橙色两种来源在视觉和图例中明确区分。用户可一目了然地看到定理的信任依赖结构。
自举的稳健路径与自我修改的绝对边界：微自举 A（表达性验证）和微自举 B（证明能力验证）提供早期闭环。可行性原型经过 Y 组合子级压力测试验证惰性复制正确性，长期稳定性测试防引用计数泄漏。首次自举目标为命题逻辑验证器，验收标准分层（基础验收=一致性+基本有效性，增强验收=完备性逼近）。自举后 C 引导核永久冻结——几何层可在沙盒内无限制演化，但沙盒墙壁不可穿透。
理论成熟度：本设计在理论自洽性上已完成封顶，在最深层的哲学、边界与实现细节上已给出精确、诚实、可审计的最终回答。四十项已识别挑战均配备工程预案，多色标记系统的自洽性已确认。
本设计已完备到可以启动阶段一开发。GeomNode 的三字段、图规范化遍引擎与作用域感知、重写匹配局部等价容忍、合一严格边界、内容哈希依赖链、多色标记信任系统（浅橙色双通道区分）、Y 组合子级可行性原型测试集与长期稳定性验证、以及 C 引导核的绝对冻结——这些将是 Lv-00 从图纸降临于代码的最终设计基石。
