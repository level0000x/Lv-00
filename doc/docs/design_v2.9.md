1. 符号坐标系统
1.1 有理数
内部表示：使用 GMP 库的 mpq_t 类型，即任意精度的分数（分子/分母均为大整数）。
规范化：坐标创建时自动约分到最简形式。分母必须恒为正整数，分子可为负。零统一表示为 0/1。
运算：加法、减法、乘法、除法均返回新的有理数节点。除法时检测除数是否为零，为零则返回错误码。
判等：化为规范形式后，直接比较分子和分母是否完全相等。
序列化：格式为 "分子/分母"，例如 "-3/4"。
1.2 代数数
内部表示：
```c
struct Algebraic {
    mpz_poly minimal_poly;   // 整数系数极小多项式（系数数组，从常数项到最高次）
    double left_bound;       // 隔离区间左端点
    double right_bound;      // 隔离区间右端点
    int precision_bits;      // 当前隔离区间的精度（有效位数）
    mpq *cached_rational;    // 若已证明等价于有理数，则缓存其值；否则为 NULL
};
```
创建：给定极小多项式和初始隔离区间。创建时必须验证该区间包含唯一实根：计算极小多项式的所有实根近似，确保以 (left_bound, right_bound) 为端点的区间与任何其他实根的区间均不重叠。
隔离区间精度管理：初始精度仅需区分极小多项式的其他实根（通常 53 位双精度即可）。更高精度仅在以下情形触发：两个不同代数数判等时，精度加倍直到足以判定不相等，或达到硬上限（2¹⁰⁰ 位 ≈ 1.27×10³⁰）。
优先有理化通路：每次算术运算后自动运行。对结果代数数计算连分式逼近（精度取当前隔离区间宽度的 1/4），产生一个有理数候选值 r_approx。在符号层将 r_approx 代入极小多项式精确求值。若多项式值为零，则该代数数等价于 r_approx，释放代数数节点并用有理数节点替换。
算术运算：加减乘除时，通过结式或代数数库（SymEngine/FLINT）计算结果的极小多项式和新隔离区间。每次运算后自动触发优先有理化通路和位数检测。
判等：先比较极小多项式（整数多项式逐系数判等）。若多项式相同，再比较隔离区间是否相交且足够精确以区分根。若多项式相同且区间重叠，则为同一代数数；若多项式相同但区间不相交，则为不同代数数（多项式有多个实根）。
平方根嵌套处理：若运算产生 √(a + b√n) 形式，先检查 a² - b²n 是否为完全平方数。若是，则结果可展开为规范的二次根式形式；否则降级为代数数或标记超界。
序列化：多项式系数列表 + 隔离区间左右端点（十六进制双精度），例如 "poly:[1,0,-2] left:-1.4142 right:-1.4141"。
1.3 二次根式
内部表示：
```c
struct Quadratic {
    mpq a, b;      // 有理数系数
    unsigned int n; // 无平方因子正整数
};
```
表示 a + b√n。
规范化：n 必须无平方因子。b = 0 时自动降级为有理数。
加法：(a₁ + b₁√n) + (a₂ + b₂√n) = (a₁+a₂) + (b₁+b₂)√n。要求 n 相同，否则降级为代数数。
乘法：(a₁ + b₁√n)(a₂ + b₂√n) = (a₁a₂ + b₁b₂n) + (a₁b₂ + a₂b₁)√n。归约到规范形式；检查是否可降级。
除法：(a + b√n) / (c + d√n) 有理化分母，分子分母同乘 (c - d√n)，分母变为 c² - d²n。若分母为零则报错。
判等：直接比较 a、b、n 三元组。三个值完全相等则为同一点。
序列化："a,b,n" 格式，例如 "1/2,1/3,2" 表示 1/2 + (1/3)√2。
1.4 超越常数
支持列表：仅限于 π（圆周率）和 e（自然对数的底）。不允许用户自创超越常数。
判等：仅同名判等——π 等于 π，e 等于 e，π 不等于 e，超越常数不与任何其他类型坐标相等。
算术：超越常数与有理数加减时保持为符号表达式（内部扩充 tensor 结构），但不保证能继续参与后继精确的代数数运算。一旦超越常数与代数数或二次根式组合，结果标记为“可能超出符号覆盖范围”。
序列化：字符串 "pi" 或 "e"。
1.5 位数熔断
检测时机：每次算术运算后的规范化和优先有理化完成后立即检测。
检测对象：计算有理数分子和分母的比特位数总和，以及多项式的每个系数的比特位数。若任何值超过 10^6 比特，则触发位数熔断信号。
熔断响应：信号沿调用栈向上返回。内核调用者（通常是求解器或重写引擎）收到信号后，暂停当前操作，记录冻结点（当前约束图的完整快照），并向用户界面报告。
用户选项：
· 忽略：接受当前节点为“数值辅助”，后续依赖该节点的构造步骤逐个阻塞，需用户逐个处理。
· 回退：恢复到冻结点状态，撤销所有中间操作，熔断被撤销。
· 永久降级为数值假设：连续触发 3 次熔断后提供。该节点永久标记为橙黄色（AMBER），其坐标由高精度数值近似替代，精确符号坐标被丢弃。
1.6 A/B 计划切换
A 计划：使用 GMP + SymEngine/FLINT 提供完整代数数支持。阶段一早期进行隔离压力测试——对 4 次以内多项式运算链连续执行 100 步，监控隔离区间精度衰减和有理数位数增长。
切换条件：连续两次压力测试中，任一以下条件未达标：
· 精度稳定性：隔离区间在连续 100 次运算后精度衰减不超过 1 bit。
· 性能稳定性：单次运算链中有理数中间结果的最大位数不超过 10^6 比特。
B 计划：切换后，所有超出二次扩张范围的代数数节点降级为数值近似（橙黄色标记）。已存在的代数数节点若能表示为二次根式则转换，否则标记。切换过程需要序列化并重新加载所有已有工程。
接口统一：两种计划的 SymbolicCoord 数据结构完全相同，仅内部 data 指向的具体类型不同。上层代码无需修改。

2. 约束图核心
2.1 节点类型
系统支持五种节点类型：
· POINT（点）：由符号坐标定义。零维。
· LINE_SEGMENT（线段）：由两个端点定义。有向，方向从第一端点到第二端点。
· REGION（区域）：由边界线段序列首尾相接形成的闭合环定义。可为简单多边形或自交多边形（自交时警告但允许）。
· PORT（端口）：函数块的对外的接口。分输入端口（实心圆）和输出端口（空心圆）。
· FUNCTION_BLOCK（函数块）：封装了内部约束子图的复合节点。存储其内部节点和约束的引用、输入/输出端口列表、以及确定性状态。
2.2 约束类型与语义
系统支持五项基本约束：
INCIDENCE（关联）：
· 点在线上：POINT 在 LINE_SEGMENT 的延长线上（不要求在线段内部）。
· 点在区域边界上：POINT 在构成 REGION 边界的某条线段上。
BETWEENNESS（之间）：
· 要求三个共线点 P1、P2、P3，且 P2 严格位于 P1 和 P3 之间。
· 也支持“点与端点重合”的边界情形——即 P2 与 P1 或 P3 重合。
INTERSECTION（相交）：
· 两条线段相交于一点。系统自动生成或识别交点。
· 线段与区域边界相交于一点。
CONTAINMENT（包含）：
· 点严格在区域内部。
· 区域完全包含另一区域。
CONNECTION（连接）：
· 端口与端口相连。有向：从输出端口连接到输入端口。
· 连接时自动触发类型兼容检查（见端口系统）。
2.3 约束图操作
添加节点：分配全局唯一 ID（自增，永不复用）。填入类型、坐标数组、端口标记字段默认值（namespace_depth=0, parent_block_id=-1, is_formal_param=false）。
删除节点：级联删除所有引用该节点的约束。对于线段节点，如果它是某区域的边界组成部分，则阻删除并报错。
添加约束：先检测是否已有相同类型且相同参与者集合的约束存在，若存在则拒绝（防重复）。对于 INCIDENCE、BETWEENNESS 和 INTERSECTION，预处理检测是否有矛盾的代数关系（如线段 AB 的长度在两个约束中被赋予不同的值）。若检测到冲突，立即标记约束为红色并向用户报告，不等待求解器。
删除约束：只删除约束记录，不删除任何节点。
冗余检测：添加新约束后，检测是否与已有约束线性相关（如三点 A、B、C，已知 AB=3，BC=4，新添 AC=7，则新约束冗余且隐含共线性）。冗余约束自动标记但不删除，在界面上以半透明显示。
区域有效性检查：创建 REGION 时，验证其边界线段是否形成闭合环（每条线段的终点连接下一条线段的起点，最后一条线段的终点连接第一条线段的起点）。不闭合则拒绝创建。自交区域允许但生成警告。
2.4 约束冲突检测（预处理）
实现机制：维护一个简化约束数据库，仅追踪代数方程层面的冲突检测（如两点间距离约束、角度约束等可导出代数方程的基本约束）。当新约束添加时，增量检查是否与已有方程产生矛盾。
冲突报告：返回冲突约束集合列表，每组包含约束 ID 和参与的节点 ID。界面上高亮这些节点和约束为红色。
局限性：预处理仅检测静态可判定的矛盾，不运行完整求解器。更复杂的间接矛盾由求解器在求解阶段发现。

3. 端口归属标记系统
3.1 数据结构
每个节点维护三个轻量级字段：
· namespace_depth（整数）：节点直接所属函数块的嵌套深度。全局画布为 0。每进入一层函数块嵌套，深度 +1。
· parent_block_id（整数）：节点直接所属函数块的唯一 ID。全局画布节点为 -1。
· is_formal_param（布尔）：仅 PORT 类型有效。若为 true，表示该端口在所属函数块内部是形式参数（输入端口）。
3.2 生命周期维护
创建全局节点：depth=0, parent=-1, is_formal=false。
打包函数块（PackFunction）：
· 输入：内部节点 ID 集合、输入端口 ID 列表、输出端口 ID 列表。
· 创建新 FUNCTION_BLOCK 节点，分配新 ID。
· 输入/输出端口节点保留在原上下文深度不变，它们作为块对外的接口。
· 所有其他内部节点的 namespace_depth 重新基化：新深度 = 原深度 - 原上下文深度 + 1。原上下文深度是执行打包时的当前画布深度。
· 内部节点的 parent_block_id 设为新函数块 ID。
· 输入端口节点标记 is_formal_param = true；输出端口标记为 false。
· 打包前先执行跨边界约束检查（见第 8 节）。
函数应用（Instantiate）：
· 输入：函数块 ID 和实参连接映射（块的输入端口 → 外部节点的输出端口）。
· 复制函数块内部所有节点和约束。
· 维护旧 ID → 新 ID 映射表（包含所有新创建的节点，以及输入/输出端口节点在复制体中的对应关系）。
· 所有复制节点的 namespace_depth = 当前上下文深度 + 原节点在块内的相对深度。
· 复制节点的 parent_block_id 保持不变（仍指向原函数块 ID），用于 β-归约时的变量捕获判定。
· β-归约连接：对于每条从形式参数端口 p 出发的内部连线，执行变量捕获判定（见 3.3 节），将连线终点重定向到实参输出端口或保持原目标。
· 输入/输出端口在归约后的重连操作中，其 is_formal_param 标记设为 false。
嵌套打包：递归应用上述规则，深度自然递增。
3.3 变量捕获消解（β-归约核心）
复制函数块内部连线时，对于每条连线的目标端口 p，进行 O(1) 判定：
· 情况 A（形式参数引用）：p.parent_block_id == 被复制块的ID 且 p.is_formal_param == true。→ 重定向到对应实参输出端口。该连线在旧图中指向块的输入端口，在新图中指向实参。
· 情况 B（自由变量引用）：p.parent_block_id != 被复制块的ID。→ 保持原连接目标不变。该连线引用的是外部变量，不应被这次 β-归约改变。
· 情况 C（内部局部引用）：p.parent_block_id == 被复制块的ID 且 p.is_formal_param == false。→ 重映射到复制件中对应的新内部节点（通过 ID 映射表查找）。
3.4 函数块确定性状态机
函数块维护以下状态：
· UNVERIFIED：打包完成，但尚未进行或完成静态分析。
· VERIFIED：静态分析在步数上限内完成且确认解唯一。
· NON_DETERMINISTIC：应用时出现过一次多解情况（即使通过选择器解决）。
· PARTIALLY_VERIFIED：静态分析未完成，但未发现冲突。
状态转换在打包时和应用时触发。转换规则见函数块章节。
3.5 端口连接的方向性与类型检查
连接方向：CONNECTION 约束是有向的——从输出端口连接到输入端口。创建连接时验证端点角色：源端必须是输出端口或全局节点（无方向），目标端必须是输入端口。
类型兼容检查：连接建立时，提取目标输入端口声明的类型区域（预期的输入类型），与源端口输出的类型区域进行类型等价检查（通过重写引擎归一化后比较）。若不等价且无法通过安全规则集证明等价，拒绝连接或标记为“未证明等价”（蓝色虚框）。
3.6 一致性断言
调试模式下检查以下不变量：
1. 任何端口的 namespace_depth 等于其 parent_block_id 指向的函数块的深度。
2. is_formal_param = true 的端口必然位于某个函数块的边界上，且该块的输入端口列表中包含此端口。
3. parent_block_id 若不为 -1，则必须指向一个有效存在的 FUNCTION_BLOCK 节点。
4. CONNECTION 约束的两端端口必须位于相同或相邻的 namespace_depth。
5. 经 Instantiate 复制后，parent_block_id 指向的函数块必须当前仍在内存中且有效。

4. 图规范化遍引擎
4.1 触发时机
· 合一检查（Unify）执行前自动调用。
· 用户通过界面显式请求“规范化视图”。
· 重写引擎不调用全局规范化——它使用内置的局部等价容忍（见重写引擎章节）。
4.2 算法流程
第一阶段：点合并
1. 遍历图中所有 POINT 节点，按符号坐标的哈希值分组。哈希基于符号坐标的规范序列化计算。
2. 对每个哈希组（大小 ≥2），内部两两执行 coord_equal() 精确判等。
3. 若一组点的坐标完全相等，检查它们的作用域归属：
   · 若 parent_block_id 和 namespace_depth 均相同（同一作用域），则自动合并。
   · 若作用域不同，生成提示信息，由用户界面弹出确认对话框（合并/保留两者/取消）。
4. 自动合并时，使用并查集处理传递闭包（A=B, B=C → A、B、C 全部合并）。每个等价类选择 ID 最小的节点作为保留代表。
5. 遍历所有约束，将引用被合并节点的参与者 ID 替换为保留节点 ID。
6. 被合并的节点从图中移除，记录到规范化日志中（合并前后 ID 对）。
第二阶段：线段和区域合并
1. 遍历所有 LINE_SEGMENT 节点，若两条线段的两个端点（经第一阶段合并后）完全对应相等，则合并线段节点。
2. 遍历所有 REGION 节点，若两个区域的边界线段序列（经第一、第二阶段合并后）完全对应相等，则合并区域节点。
第三阶段：稳定化
1. 对约束图进行拓扑排序稳定化：按节点 ID 升序遍历约束的参与者列表，重新排列参与者 ID 的顺序以产生唯一确定的约束表示。
4.3 幂等性保证
规范化算法设计保证幂等：规范化后的图再次运行规范化不会产生任何变化。这通过以下方式实现：
· 每次合并保留最小 ID 作为代表（确定性的选择）。
· 第二阶段和第三阶段使用固定的遍历顺序（按 ID 升序）。
· 规范化前不假设图已有任何规范形式。
4.4 规范化日志
每次自动化规范化记录以下信息：
· 合并的节点 ID 列表（旧 ID → 保留的新 ID）。
· 是否为自动合并还是用户确认后合并。
证明导航器可展开此日志，以灰色虚影显示被合并的节点，以高亮显示保留的节点。

5. 符号代数求解器
5.1 代数方程转化
求解器从约束图中提取代数方程：
· INCIDENCE 约束：点 P 在线段 AB 的延长线上 → (P - A) × (B - A) = 0（叉积为零，线性方程）。
· BETWEENNESS 约束：不增加独立代数方程，仅用于在多个解中选择符合方向性约束的那个。
· INTERSECTION 约束：两条线段相交 → 参数化后产生线性方程组。
· 距离约束（公理包模板展开后）：两点 AB 距离为 d → (x_A - x_B)² + (y_A - y_B)² = d²（二次方程）。
· 平行/垂直约束：线性关系（斜率相等或点积为零）。
5.2 求解流水线
第一步：几何推理消元
· 应用预定义的几何定理模板：相似三角形比例式、勾股定理、平行线截线段比例定理等。
· 这些模板将已知的几何关系直接转化为代数等式，进行变量消元。
· 优先消去可线性求解的变量。
第二步：Gröbner 基求解
· 仅对消元后仍无法线性求解的子系统使用。
· 变量顺序按图的依赖关系排列（被依赖的变量排在前面）。
· 仅处理二次及以下的多项式系统。若检测到不可约三次及以上的方程，立即标记“超出范围”并返回。
第三步：“超出范围”分析
· 求解器遇到不可约高次方程时，不直接报错退出。
· 分析方程结构：尝试对多项式进行因式分解。若可分解为多个二次及以下因子，系统提示“可通过引入辅助线将问题拆分为多个二次步骤”，并高亮潜在的拆分点。
· 若方程为不可约高次，提示“该问题在当前公理包下可能不可构造，可尝试归约至已知不可构造问题”。
5.3 多解处理
当二次方程产生两个候选解时（例如圆与直线相交于两点），求解器生成两个可能的符号赋值分支。它不自动选择分支，而是返回多解信号给上层调用者（函数块应用或交互界面）。上层通过选择器或用户交互来决定采用哪个分支。
5.4 过约束检测
在求解过程中，若代数化简推出矛盾等式（如 0 = 1），求解器立即停止对该子系统的求解，标记所有涉及当前待求解变量的约束为冲突约束集，并以红色高亮。
5.5 自由度计算
求解完成后，报告仍未完全约束的自由节点数量及它们的 ID。这些节点在探针系统中显示为灰色（有自由度）。
5.6 增量求解
求解器维护“脏”变量集合——自上次求解以来被修改或新增约束影响的变量。新的求解请求只对脏变量相关的最小依赖子图重新运行消元和求解，未受影响的变量保持其已知解不变。

6. 图重写引擎
6.1 重写规则定义
每条规则包含：
· 匹配模式（pattern）：一个约束子图模板。其中“变量节点”的 ID 用负数表示，象征可绑定到任意实际节点。模式约束仅涉及这些负 ID 节点和可选的已有具体节点。
· 替换模式（replacement）：一个约束子图，其中节点 ID 引用模式中的负 ID 变量。替换时可包含新节点（用特殊标记），这些新节点在规则应用时创建。
· 约简测度（reduction_measure）：整数。正值表示规则应用后某个度量（节点数、约束数、代数次数）的减少量；0 表示无测度；负值表示扩展规则（仅用户显式触发）。
· 前置条件（condition）：可选的附加条件表达式。支持代数比较（如两线段长度比 > 1）和几何包含（某点在某区域内）。在模式匹配成功后、执行替换前评估。
6.2 匹配算法
使用改进的 VF2 子图同构算法，特殊之处在于：
· 对于 POINT 节点，匹配条件不要求节点 ID 相同，而是调用 coord_equal() 进行符号坐标判等。这使得“坐标相同但 ID 不同”的两个点被视为可匹配，即局部等价容忍。
· 这避免了在重写前需要调用全局规范化遍的依赖。
6.3 替换操作
· 根据模式匹配产生的绑定映射（负 ID → 实际节点 ID），复制替换模式并实例化到目标图中。
· 重连边界：替换模式中引用外部节点的连接，在替换后重新定向到正确的实际节点。
· 旧子图（被匹配的部分）被分离并从约束图中移除（若不再被其他部分引用则完全删除）。
6.4 引擎控制循环
1. 新约束添加后，或用户触发重写时，引擎被唤醒。
2. 按约简测度降序遍历所有可用规则。相同测度则按规则注册顺序。
3. 每条规则尝试与全图匹配。若有多个不重叠的匹配位置，选择“最佳匹配”（匹配子图节点数最多）。
4. 若规则有前置条件，在匹配成功后评估条件。条件不满足则跳过此匹配。
5. 执行替换。替换后立即验证约束图是否产生新的冲突（与已有约束的代数矛盾）。若产生冲突，回滚整个替换操作（事务性回滚），恢复图状态，并记录该规则在此上下文的失败以避免无限重试。
6. 每次成功应用规则，全局步数计数器 +1。达到步数上限时暂停并提示用户。
6.5 步数熔断
· 全局步数上限可配置，默认 1000。
· 超限后，重写引擎暂停，所有当前匹配状态被保存。用户界面提示，用户可选择继续（重置上限或增加上限）或终止当前重写批次。
6.6 图哈希循环检测
· 基于 WL（Weisfeiler-Lehman）图核计算结构哈希。时间复杂度 O(E)。
· 初始节点标签基于节点类型和约束拓扑（忽略坐标值，基于邻居关系）。
· 执行 2 轮 WL 迭代，聚合邻居标签。
· 最终哈希为所有节点标签的异或组合。
· 维护最近 16 步图哈希的环形缓冲区。若新哈希与缓冲区中任一值相同，暂停并报告“检测到可能的重写循环”。
· 即使哈希碰撞导致误报，仅触发暂停而非崩溃，用户可选择忽略继续。
6.7 规则管理
· 规则可从 .lvz 规则包在运行时热加载，也可在运行时卸载。
· 卸载规则不影响已应用该规则的历史步骤（历史状态不可改写）。
· 用户可在规则优先级列表中手动调整顺序。

7. 约束模板系统
7.1 模板定义
每个模板在注册时提供：
· 名称：字符串，如 “distance_between”。
· 参数列表：每个参数的类型（POINT/LINE_SEGMENT/REGION/SCALAR）和数量。
· 展开函数：接收参数的实际节点 ID 或符号坐标值，在目标约束图中生成等价的基本约束组合。
· 正则形式描述：一个约束图的“骨架”——仅指定约束类型和节点类型的组合模式，不涉及具体坐标值。用于验证展开结果是否符合该模板的规范形态。
7.2 模板展开
· 调用时，参数类型首先被校验——不匹配则拒绝展开。
· 展开结果缓存：以参数哈希（所有参数值的符号坐标哈希组合）为键缓存展开后的约束图片段。后续相同参数可直接复用。
· 若展开过程中引用其他模板，则递归展开至多 8 层。超过深度时拒绝展开并报错。
7.3 正则形式强制验证
· 模板通过双层测试集时，不仅验证展开结果的语义等价性，还验证展开结果的图结构是否匹配其声明的正则形式描述。
· 例如“两点距离为 d”模板的正则形式规定：展开后必须产生一条线段节点，且该线段仅涉及 INCIDENCE 关系（端点和线段关联），不得使用辅助点或更复杂的约束组合。
· 若模板实现使用了辅助构造（如引入第三个辅助点），测试集将拒绝，因为展开结果不符合正则形式。
7.4 双层测试集
出厂测试集：硬编码于内核。由内核开发者手工编写，每个用例包含：模板实例化参数、展开后的约束图预期、目标度量公式的计算结果、手工判定的预期结果（通过/失败）。内核在启动时自动运行。
用户测试集：公理包作者在 .lvz 文件中提供，格式与出厂测试集相同。在加载公理包时运行。
模板通过标准：通过全部出厂测试 + 用户测试（若有），且正则形式验证通过。
7.5 调试视图
当用户检查涉及模板的约束冲突时，可请求“展开视图”——将模板实例临时替换为其展开的完整基本约束图，在界面上高亮冲突的具体基本约束。日常交互中模板保持压缩态（以模板名称和参数列表显示）。

8. 函数块
8.1 打包操作（PackFunction）
输入：内部子图节点 ID 集合、输入端口 ID 列表、输出端口 ID 列表。
打包前强制检查——跨边界约束：
· 遍历图中所有约束，识别涉及两个节点集合（内部节点集合 vs 外部节点集合）的非 CONNECTION 约束。
· 这些约束是“跨边界约束”——封装后它们将被函数块边界遮挡，外部不再可见。
· 系统弹出打包冲突对话框（GUI 模式下）或返回冲突列表（API 模式下），逐个列出冲突约束和涉及的端口。
· 用户对每条冲突约束三选一：
  · 提升：该约束成为函数块的端口依赖，记录到函数块节点的附加属性中。在图形上，对应端口旁显示小图标（INCIDENCE: 短线穿点；CONTAINMENT: 小圆含小点；BETWEENNESS: 三点一线）。在文本模式下，对应函数签名的附加条件。
  · 断开：删除该约束。用户确认封装后此约束不再需要。
  · 取消：放弃本次打包，返回编辑状态。
· 全部冲突解决后，打包继续。
打包执行：按 3.2 节描述的规则更新所有内部节点的端口归属标记，创建函数块节点。
8.2 确定性检查
静态层（打包时）：
· 对内部约束图进行快速静态分析。
· 若内部是线性约束系统，解的存在唯一性可在多项式时间内判定。若有唯一解，函数块标记为 VERIFIED。
· 若内部涉及二次约束，使用符号代数引擎尝试消元并计算解的个数。若在步数上限（默认 100）内完成且确认为唯一解，标记为 VERIFIED。
· 若静态分析未能在步数上限内确认唯一性但未发现冲突，标记为 PARTIALLY_VERIFIED，允许使用。
动态层（应用时）：
· 函数块被例化时，求解器计算具体输入下的实际输出。
· 若产生唯一解，正常输出，VERIFIED 状态维持；PARTIALLY_VERIFIED 可升级为 VERIFIED。
· 若产生多解且用户未提供选择器，应用被拒绝并提示“该函数在此输入下产生多解，请提供选择器”。
· 若产生零解，报告“无解——输入不满足前置条件”。
· 第一次出现多解后，函数块降级为 NON_DETERMINISTIC。此后每次应用都需要选择器。
8.3 多解选择器
· 函数块定义时可预提供选择器。选择器是用户指定的过滤条件，如：“取正根”、“取位于区域 A 内的交点”、“取距离点 P 最近的解”。
· 应用时若多解出现，选择器自动过滤候选解。若过滤后仍有多解，报错要求更精确的选择器或手动选择。
· 选择器作为函数块定义的一部分存储。
8.4 部分应用（柯里化）
· 若函数块有多个输入端口（如 f: A→B→C），允许在应用时仅连接部分输入（仅连接 A，不连接 B）。
· 系统内部创建新函数块包装原块，将已连接的实参 A 固化到内部，剩余输入端口 B 暴露为新函数块的输入端口。返回的新函数块类型为 B→C。
8.5 函数块组合子
预置的几何化组合子块（可被任何公理包使用）：
· Compose：接受 f: A→B 和 g: B→C，产生 g∘f: A→C。内部将 f 的输出端口连接到 g 的输入端口。
· Product：接受 f: A→B 和 g: C→D，产生 f×g: A×C→B×D。内部将两组端口并列。
8.6 视图折叠/展开
在界面中，函数块可以折叠为单个盒子（只显示输入/输出端口和块名称）或展开显示完整内部构造。折叠/展开状态保存在视图层，不改变底层约束图。

9. 递归与条件
9.1 递归构造
· 函数块内部可引用该函数块自身的输入/输出端口（自引用）。
· 递归块在打包时必须声明测度：一个几何量（如线段长度、区域面积）及其上的良基关系（如严格小于）。
· 每次递归调用时，系统调用测度递减性检查，确保递归参数在测度上严格递减。
9.2 测度系统
符号测度：可归约到符号坐标上的代数表达式（如两点距离由代数表达式给出）。递减性由内核的代数不等式引擎直接判定——计算两次调用的测度值之差，判断是否 < 0。此判定与公理包的构造子无关。
非符号测度：公理包定义的抽象序结构（如某种自定义的偏序）。此类测度的递减性检查由公理包的一级模板以硬编码方式提供——模板展开为等价的基本约束图，内核求解器执行该展开图的递减性判断。公理包加载时，若检测到非符号测度，系统提示用户“该测度的递归终止性依赖公理包作者的模板正确性”。
加载时验证：公理包注册非符号测度类型时，需在模板元数据中声明“非符号测度比较器”。系统在模板形式化测试阶段，通过包含测度递减性验证用例的测试集，验证声明与实际行为一致。
9.3 互递归支持
两个函数块可互相引用对方的端口（如 f 调用 g，g 调用 f）。互递归的测度检查要求两者在同一个全局测度下各自递减。系统在递归调用的调用链上追踪测度值，确保沿着调用链方向单调递减。
9.4 递归深度监控
系统维护递归调用深度计数器。每次进入递归调用时 +1。达到上限（默认 10000）时暂停，提示用户可能的无限递归。用户可选择继续（提升上限或忽略此次警告）或终止。
9.5 条件/选择器块
选择器块是一个特殊结构，有两个分支子图。基于几何包含关系的判定结果：
· 若判定为“点在区域内”，激活匹配的分支子图（实线显示）。
· 不匹配的分支子图保持虚影（灰色半透明）。
· 若包含关系未确定（区域边界未清晰界定或点在边界上），两个分支均保持半透明，提示需要更多约束。

10. 命题与证明系统
10.1 命题模式定义
命题以虚线框表示，内含：
· 输入/输出端口：声明命题期望的证物应具备的外部端口。
· 等待填充的几何模式：虚线绘制的约束骨架，表示证物构造需满足的几何结构。
· 前置条件区域（可选）：声明输入应满足的额外几何约束（如“输入点A必须在区域R内部”）。
· 后置条件（可选）：声明输出应满足的额外约束（如“输出线段的长度>0”）。
10.2 合一检查（Unify）
合一检查在证明完成时调用，判断构造是否满足命题。
执行流程：
1. 对构造图和命题模式图各自执行图规范化遍（Graph Normalization Pass）。
2. 展开命题模式中的所有约束模板实例为正则形式的基本约束图。
3. 执行三层匹配：
   · 端口类型匹配：构造的输出端口类型与命题声明的输出端口类型是否一致。类型等价通过重写引擎归一化后比较。
   · 约束类型匹配：命题模式中的每个约束，在构造图中寻找对应约束。比较约束类型和参与者节点。节点通过符号坐标判等匹配（允许不同 ID 但坐标相等）。
   · 符号坐标判等：约束的坐标参数在代数判等下完全相等。
4. 若所有层面匹配成功，合一通过。命题虚线框变为实线（命题得证）。
5. 若任何一层匹配失败，返回失败并报告不匹配的具体位置（哪个约束、哪个节点未匹配）。
严格边界：合一不调用约束求解器来判定语义等价。任何语义等价但结构不同的构造需要用户通过重写规则显式化简。图规范化遍仅在符号坐标严格相等时合并冗余节点。
10.3 命题的等价变换
用户可声明两个命题模式等价（如 P∧Q 等价于 Q∧P）。等价声明被存储为双向重写规则，在合一前自动应用以在两种结构形式间转换。
10.4 命题的实例化
对于多态命题（如“对任意集合A，A⊆A”），用户可将类型变量替换为具体类型区域（如“三角形集合T”），生成具体命题实例供证明。
10.5 ⊥（矛盾）的公理包可定义性
⊥ 不是硬编码的全局节点。每个公理包定义：
· ⊥ 的几何表示：默认为无可填充端口的空模式——一个仅有输入端口（接受证物 A）而无输出端口的几何模式。任何试图与 ⊥ 合一的构造必然失败（无可匹配的输出端口）。
· ¬ 的编码：默认为 A → ⊥（标准 BHK 解释）。可被公理包覆盖为其他几何编码。
· 矛盾推导行为：默认阻塞推导（对应直觉主义逻辑——从矛盾不能任意推导）。可被公理包覆盖为爆炸原理规则（从 ⊥ 可推导任意命题 P）。
10.6 爆炸原理（Ex Falso）
若公理包定义了爆炸原理，系统提供预置函数块 ex_falso_quodlibet：
· 输入端口类型 = ⊥。
· 输出端口类型 = 可变的 P（任意命题）。
· 内部包含特殊标记节点 “ex falso quodlibet”。
· 应用时，在证明图中从 ⊥ 到 P 产生一条浅橙色虚线箭头，标注“ex falso”。
· 此步骤在证明导航器中作为独立步骤记录，与非构造性 oracle 依赖（浅橙色实心端口标记）在视觉和图例中明确区分。
10.7 证明导航器
步骤幻灯片回放：证明的每一步（添加节点、添加约束、重写步骤、函数应用等）作为独立步骤可前后导航。
自动规范化步骤：规范化前后的约束图对比可视化——合并的冗余节点以灰色虚影显示，保留的节点以高亮显示。
依赖关系图：每个步骤可查看其依赖的前驱步骤和影响的后续步骤，以有向图呈现。
引理块折叠：嵌套引理可折叠以管理复杂度。折叠时显示引理名称和证明状态着色。
导出格式：
· 交互式 HTML（保留步骤导航和几何视图）。
· LaTeX 证明文本（线性化步骤描述）。
· Coq/Lean 调用序列（对外部可信基的引用序列）。
断点与续证：证明过程中可设置断点（蓝色未完成标记），保存工程后关闭。重新打开时从断点继续构造，上下文完整恢复。
全色标记图例：证明导航器始终显示颜色图例，解释每种颜色的语义：
· 绿色：全构造，无任何非常规依赖。
· 蓝色（三子类）：待完成的证明义务。
· 绿色实框：已证不可构造（有形式化支撑）。
· 黄色虚线框：条件性不可构造（依赖作者断言或依赖已失效）。
· 浅橙色实心端口标记：依赖非构造性 oracle 块。
· 浅橙色虚线箭头标记：包含爆炸原理步骤。
· 橙黄色：含数值假设。
· 深橙色：非构造性依赖与数值假设叠加。

11. 不可构造性证明
11.1 蓝色虚框的子状态
当某个构造目标被标记为“待完成的证明义务”时，蓝色虚框附带子状态：
· 蓝色（未探索）：默认状态，尚未主动穷尽构造空间。
· 蓝色（资源受限）：步数熔断或求解器超时触发。
· 蓝色（超出范围）：求解器报告超出其代数覆盖范围。
11.2 归约式不可构造性证明
用户使用不可构造性证明模板：
1. 输入目标构造问题（如“三等分角”）。
2. 输出一个已知不可构造问题（如“倍立方体”）的构造。
3. 用户在模板内完成归约构造（仅使用当前公理包的全部许可构造子）。
4. 若归约构造通过合一检查，且目标已知不可构造问题被公理包标记为不可构造，则蓝色虚框转为“已证不可构造”标记。
11.3 构造空间穷举工具
用户可对蓝色“未探索”目标触发穷举工具。对尺规公理包，系统自动尝试有限组合路径（限定构造步数和辅助点数量）。结果：
· 若找到构造 → 转化为绿色证物。
· 若穷举空间内无构造 → 转为“未发现构造”（蓝色，可进一步转不可构造分析）。
· 超时 → 转为“资源受限”蓝色。
11.4 依赖链引用格式
公理包的“已知不可构造问题列表”中，每个条目通过依赖链字段引用其依据来源：
内引用：指向公理包内的一个引理块，记录该引理块的唯一标识符及其内容哈希。内容哈希计算如下：
· 提取引理块的约束图规范表示：按拓扑序重新编号节点，序列化为标准邻接表格式（节点类型 + 约束类型 + 符号坐标规范表达式）。
· 不包含块名称、注释、视觉布局信息、原始节点 ID 等元数据。
· 对规范表示计算 SHA-256。
· 加载时重新计算内容哈希并与存储值比对。哈希相同 → 数学内容未被修改。哈希不同 → 触发降级。
外引用：规范引用字符串，指向公认文献（如“Wantzel 1837”）。外引用被视为永久有效，可选附带“信任注释”（验证状态和时间戳），不参与自动重验。
作者断言：引用字段为空或标记为“公理包作者断言”。系统立即将其识别为黄色基础。
11.5 依赖链断裂自动降级
公理包升级后，系统自动重验所有内引用并重新计算内容哈希：
· 若内引用指向的引理块内容哈希变化 → 依赖链断裂。
· 绿色结论自动降级为黄色“条件性不可构造——依赖已失效”。
· 系统提示用户该结论需重新验证。
· 若断裂的引用后续被修复（用户手动重证了引理块，使其内容哈希再次匹配），恢复绿色。
· 降级不影响已完成的归约证明的合一检查结果，只影响结论的着色与信任级别。
11.6 交互式证明辅助
提供向导模式引导用户完成不可构造性证明：
1. 选择目标构造问题。
2. 从已知不可构造列表中浏览和选取归约目标。
3. 在画布上逐步构建归约映射。
4. 系统实时验证归约步骤的正确性。
5. 完成时自动着色（含依赖链追溯）。
11.7 新不可构造结果的登记
用户完成一个新的不可构造性证明后，可将结果登记到公理包的已知不可构造问题列表中。登记时需填写所有依赖链引用。后续证明可引用此新增条目。

12. 类型系统与宇宙层级
12.1 宇宙层级机制
默认启用良基宇宙层级：
· 第 0 层：基本几何体（点、线段）。
· 第 1 层：由基本几何体构成的类型区域（如“所有线段的集合”）。
· 区域只能包含严格低于其层级的几何体。
层级检查在公理包层实现，作为公理包定义的有效性规则。内核保持本体论中立，不强制层级，只提供几何基础设施。
12.2 累积性
第 n 层的类型也自动属于第 n+1 层（累积宇宙）。实现为：层级检查时，第 n 层对象可以出现在第 n+1 层区域的内部而不报错。
12.3 非良基模式
非良基集合论公理包（如 Aczel 反基础公理）可关闭层级检查，代之以解引理等非良基相容性约束。关闭后：
· 约束图中可能出现循环包含结构（A 包含 B，B 包含 A）。
· 这些结构在几何上对应非良基集合，是合法的数学对象。
· 包含关系是图拓扑关系而非代数方程，不增加求解器的代数负担。
· 步数熔断和循环检测防止沿包含关系无限展开。
12.4 多态类型
函数框中的类型区域可以是虚线框——可替换的类型变量。当函数应用到具体类型时，类型变量被替换为具体类型区域，自动适配。
12.5 依赖类型 Π(x:A).B(x)
函数块的输出类型区域由输入值通过确定构造给出。在端口连接时（编译期），类型等价通过将输入值代入输出类型构造后，与目标类型进行图重写判等来完成。
12.6 类型等价检查
端口连接时：
1. 重写引擎使用核心安全规则集（受汇合性担保）尝试将两个类型区域归一化。
2. 若两者归约到相同范式，连接有效。
3. 若自动重写无法归一化，不立即判定“不等价”。报告“未能证明等价”，同时开放交互式路径探索器：用户手动选择重写路径、回溯、尝试替代规则。
4. 若用户找到使两者合一的重写路径，等价成立，该路径被记录并可回放。
12.7 类型推断
当端口连接时，若一端类型未声明（类型区域为空），系统尝试从另一端推断类型：
· 推断规则：沿集合包含链、函数块输入输出关系推断。
· 推断结果自动填充到未声明的一端。
· 若无法唯一推断，提示用户手动指定。
12.8 类型别名
用户可为复杂类型区域定义别名（如“Triangle ≡ 三个不共线点构成的区域”）。别名存储在工程中，在类型等价检查时自动展开。

13. 高维结构表示与交互
13.1 核心原则
四维及以上的数学对象不以直接二维图形表示，而是通过端口抽象块承载。二维矩形编码仅为投影视图之一。
13.2 投影机制
每个高维抽象端口块强制附带用户可自定义的二维投影视图。
投影声明：用户指定维度映射规则——哪些高维坐标轴映射到画布 X、Y 轴，其余维度折叠或丢弃。映射可包含线性变换（旋转、缩放）以优化可视效果。变换矩阵可保存为预设。
单向保真原则：投影中可见的任何几何关系在底层结构中必然成立。若底层关系的某种几何表现无法在当前投影中忠实表达，系统强制隐藏该关系，绝不允许假阳性显示。
元数据标注：被折叠维度的信息以淡色文字标注在投影区域旁。
投影切换：用户可快速切换预设投影视角（下拉菜单或快捷键）。
保真度指标：每个投影显示一个“保真度”百分比，表示底层关系中能在当前投影中可见的比例。计算方式：可见关系数 / 总关系数。低于 50% 时提示用户切换投影。
多投影并排视图：支持同时打开同一高维块的 2-4 个不同投影视图，并排显示。用户在一个视图中悬停或选中元素时，其他视图联动高亮对应元素。
13.3 语义缩放
通过语义缩放进入高维块的“内部透视”——当前画布上下文切换为以该块为主视角的局部坐标系，高维结构被投影展开。离开该块则回到上层视图（类似文件系统的进入/退出文件夹）。
13.4 高维证明的信任锚点
在投影视图中，用户无法“看见”底层结构全貌，但每次端口连接操作都对应底层的图结构匹配（含图规范化遍）。正确性信任从“视觉直觉”迁移至“端口连接操作严格保真”。

15. 持久化与版本管理
15.1 .lvz 文件格式
二进制格式：使用 MessagePack 序列化。结构包含：
· 文件头：magic number "LVZ0"、版本号、元数据（作者、时间戳、依赖公理包列表）。
· 节点数组：每个节点序列化为 [type, id, coords, coord_count, trust_color, lo_subtype, namespace_depth, parent_block_id, is_formal_param, ...]。
· 约束数组：每个约束序列化为 [type, participants_ids, n_parts, template_id, template_params...]。
· 函数块定义：引用内部节点 ID 范围、端口 ID。
· 命令日志：自上次快照以来的增量命令序列。
文本格式：使用 YAML 子集，字段与上述二进制结构一一对应，用于可读存储和版本比较。
15.2 自动保存与崩溃恢复
· 每 30 秒自动保存当前工程到临时文件（~/.lv00/autosave/项目名.lvz.tmp）。
· 正常保存或退出时删除临时文件。
· 启动时检测临时文件是否存在——若存在，提示“检测到未保存的工作，是否恢复？”用户确认后加载临时文件。
15.3 增量存储
完整工程快照 (snapshot) 加上增量命令日志 (command log)：
· 首次保存生成完整快照。
· 后续保存仅追加命令日志（从上次快照到当前的命令序列）。
· 命令日志达到一定长度（默认 1000 条）后，触发新快照生成（合并日志到新快照并清空日志）。
· 这减少存储空间占用和保存时间。
15.4 版本控制
· 基于命令日志的版本管理。每次保存可在 Git 中提交。
· 几何差异比较：加载两个版本的约束图，计算图结构差异（新增/删除的节点和约束）。差异以可视化方式呈现（绿色=新增，红色=删除，黄色=修改）。
· 协作合并：基于命令日志的 CRDT 策略。冲突时（两人修改同一节点/约束）可视化展示两个版本供用户选择。
15.5 内容哈希依赖链
引理块存储时计算内容哈希（SHA-256），计算方式：
· 提取约束图的规范表示：按拓扑序重新编号节点，仅序列化约束类型、节点类型、符号坐标的规范表达式。
· 不序列化块名称、注释、视觉布局信息、原始节点 ID。
· 加载时重新计算并与存储值比对。哈希不同则标记依赖链断裂。
15.6 导出格式
· 独立演示包：将工程打包为单文件 HTML（内嵌 WebAssembly 版内核 + 工程数据），可在浏览器中独立查看和交互（只读模式，保留缩放、导航、探针功能）。
· SVG/PDF：导出当前画布视图为矢量图。

17. 自举层
17.1 λ-演算几何表示
λ-抽象 λx.M：表示为一个标准的 Lv-00 函数块。输入端口对应形式参数 x，块内部的节点和连线构成 M。所有对 x 的引用都连接到该输入端口。
α-等价的自然退化：两个仅在变量名上不同的 λ-项产生完全相同的端口连接图结构，α-等价在几何表示中无需额外规则。
β-归约：函数应用 (λx.M)N 的几何配置中，λ 块的输入端口连接 N 的输出端口。重写规则检测此模式，执行第 3.3 节的变量捕获消解和替换。
17.2 let/where 绑定
语法糖支持：
· let x = 构造 in 主体 → 脱糖为 (λx.主体) 构造。
· 主体 where x = 构造 → 脱糖为 (λx.主体) 构造。
  在界面上以可读形式显示，内部存储为 λ-应用。
17.3 模式匹配
对和类型（∨）的模式匹配实现为选择器块的泛化：
· 分析析取证物的标记（tag）。
· 根据标记选择对应分支子图。
· 不匹配的分支保持灰色虚影。
17.4 固定点组合子
Y 组合子作为递归的标准实现：
· Y = λf.(λx.f(x x))(λx.f(x x))
· 在 Lv-00 中，Y 组合子本身是一个函数块，内部包含自引用端口。
· Y F 单步展开 → F(Y F)：验证自引用端口的 parent_block_id 传递正确性。
· Y F 3 多步归约到范式（如 3! = 6）：验证深层递归展开中共享子图的引用一致性。
终止性安全机制：Y 组合子只能用于递归测度可判定的场景。当测度不可判定时，添加额外步数限制。用户可手动设置最大递归展开次数。
17.5 命题逻辑验证器
在 Lv-00 中用几何构造实现命题逻辑验证器，遵循 BHK 解释：
· 原子命题：表示为单位区域（类型区域）。
· ∧（合取）：乘积类型函数块。接受两个证物（左证物和右证物），输出配对区域。
· ∨（析取）：和类型函数块。接受一个证物，输出带标记的析取证物（左注入或右注入）。
· →（蕴含）：标准函数块。接受一个证物，输出一个证物。
· ¬（否定）：默认定义为 A → ⊥。
· ⊥（矛盾）：公理包可定义。默认无可填充端口的空模式。
验证器工作流程：
1. 接收一组前提命题的几何模式和一个目标命题的几何模式。
2. 通过函数应用和函数块打包，将前提证物逐步组合，向目标模式逼近。
3. 若最终构造与目标命题模式合一成功（含图规范化遍），命题得证。
17.6 自举验收标准
基础验收（宣布自举成功的最低标准）：
· 命题逻辑验证器通过精选烟测集（由公理包作者精选的直觉主义命题逻辑定理与谬误，以 .lvz 工程文件发布）。
· 正向烟测：验证器应产生合一证物。
· 负向烟测：验证器应报告“未能证明”。
· 此标准验证一致性（不矛盾）和基本有效性。
增强验收（自举后持续改进）：
· 自动测试生成器随机生成命题逻辑公式。
· 比较验证器证明结果与经典真值表（经 Glivenko 翻译或双重否定翻译至直觉主义逻辑）。
· 以通过率作为完备性逼近的公开指标。
自举完备性报告：自举成功后自动运行基准测试套件（100+ 随机命题），生成 HTML 报告，包含：
· 成功证明率。
· 失败原因分布（超时/超出范围/真正不可证）。
· 平均重写步数和求解时间。
17.7 引导器冻结
自举成功后，C 内核进入永久冻结状态：
· 内核代码文件在文件系统上设为只读。
· 内核只暴露只读服务接口。几何层可在抽象阶梯上无限演化（修改逻辑规则、编译策略、重写引擎的几何层编排），但所有几何层操作最终必须通过冻结的 C 内核 API 执行。
· 冻结后内核可执行文件的哈希值公开发布，任何第三方可验证未被篡改。

18. 系统基础设施
18.1 内存管理
· 专用内存池：内核使用内存池（chunk-based allocator）管理 GeomNode 和 Constraint 的分配。内存池以固定大小的块（chunk，如 64KB）为单位从系统申请，内部按需分配。减少 malloc 碎片，提高缓存局部性。
· 节点和约束的分配优先从空闲链表（free list）复用已释放的内存槽，而非立即归还系统。
· 内存池在工程关闭时整体释放。
18.2 引用计数与垃圾收集
· 所有 GeomNode 和 Constraint 维护引用计数。引用计数包括：约束图中的直接存在、其他约束对其的引用（参与者）、函数块内部的包含关系。
· 引用计数归零时，节点/约束放入空闲链表，不立即释放内存。
· 对于极少数的循环引用情况（如 A 包含 B，B 包含 A），周期性运行标记-清除（mark-sweep）检测。标记阶段从全局画布和所有活跃函数块的入口遍历可达对象，清除阶段回收不可达对象。
18.3 错误处理
· 内核 API 返回错误码（int 类型，0 表示成功，负值表示具体错误类型）。不抛出异常，不调用 longjmp。
· 致命错误（内存耗尽、数据损坏检测）：触发安全停机流程——
  1. 将当前约束图序列化到紧急保存文件（~/.lv00/emergency/时间戳.lvz）。
  2. 记录调用栈和错误信息到日志。
  3. 弹出对话框告知用户，并退出。
· 非致命错误（类型不匹配、约束冲突等）：返回错误码，不改变系统状态。
18.4 日志系统
· 分级日志：DEBUG < INFO < WARN < ERROR。
· 调试模式下记录所有级别的日志。
· 正式运行仅记录 WARN 和 ERROR。
· 日志输出目标：文件（~/.lv00/logs/lv00.log，轮转方式，最多保留 5 个文件，每个最大 10MB）。
· 日志格式：[时间戳] [级别] [模块] 消息内容。
18.5 性能计数器
内核维护以下全局计数器：
· 总节点创建数/当前存活节点数。
· 总约束创建数/当前存活约束数。
· 求解器调用总次数/平均耗时。
· 重写引擎总步数/规则应用次数。
· 合一检查总次数/成功次数。
· 内存使用峰值（字节）。
计数器可通过 API 查询，用于性能调优和自举完备性报告。在界面中可显示为开发者面板。
